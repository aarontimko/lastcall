## Deliverables

**One worker. Deliverables 1–2, then the sanctioned checkpoint (verifier (a) hunts the listing change), then 3–8; verifier (b) after 8. Every deliverable that changes a frame names the snapshots it regenerates in its commit message and updates the `tui.md` "Design pass inputs" row that pins the rule.**

1. **`status` names its store (Amendment v1.9 item 3; `status_version` stays 1).** `status --json` gains top-level `state_dir` (the resolved absolute path) and per-root `store` (the `<repo-hash>` directory name) and `ledger_written_at` (the ledger file's mtime as ISO-8601 UTC, `null` when no ledger exists yet). `lastcall status` (human form) prints `state dir: <path>` as its first line. `lastcall config` unchanged. The golden regenerates once (`just golden-update`); the test normalises `state_dir` to `<S>`, every `store` to `<H>` and every `ledger_written_at` to `<T>`, and its leak assertion becomes "the state dir appears only in `state_dir`". Tests: `status_json_names_the_state_dir_and_each_roots_store`; `engine.md`'s schema section gains the three fields. *Why first:* it is the hardening the closed §11 entry asked for, and the checkpoint verifier reads it.

2. **Every repo stays on the nav; empty repos can be hidden (ruling R2; §6.7 Amendment v1.9 items 1 and 4; §6.1 item 2).** The sponsor's design, verbatim in substance: "always display the git repo … even if there's no changes staged within it … when I accept the last file, the cursor goes to highlight the repo name … a simple keyboard toggle to hide repos that have nothing in them … by default you would always see every repo".
   1. *Listing rule:* `App::is_listed(view)` becomes `loading.is_none() && !scope_pending && in_scope(path) && (!self.hide_empty || view.listed() || attention flag)`. A repo with no rows is a **name-and-branch row with no file rows under it**, rendered dim (name still bold-dim, the same dot/badge/remote spans as today), separated by the same horizontal rule; it is selectable by key and by click like any root row. The right pane for a selected empty repo reads `nothing pending in <name>` (its branch line beneath, as the root summary does today); the `None` arm's `nothing pending across N repos` stays only for the zero-repos-listed case (every repo hidden by `t`, or under a scope — the scoped text is unchanged). The **header** keeps its live counts (`N repos` counts every root under the parent, as today; files/hunks unchanged). `lastcall status` and `status --json` are **not** changed by this deliverable (the CLI never listed repos by pending state).
   2. *The toggle:* new keymap action `hide_empty` bound to **`t`** (`[keys] hide_empty = "…"` overrides it); it flips `App.hide_empty`. Hint line, tier 1: `t hide empty` while showing all, `t show empty` while hiding (the label follows the state — the sponsor: "a simple little show/hide repos … on the bottom instructions"). Help overlay row: `t  hide / show repos with nothing pending`. Default from config: **`hide_empty_repos = false`** (top-level bool, §6.1; `lastcall config` prints it; an unknown-type value is a load error like every other key). The herdr scope (`w`) and this toggle are **independent filters**: `w` shows the roots the workspace scope hides, `t` hides the roots with nothing pending among the ones in scope; the scope notice is unchanged.
   3. *The cursor after a row goes away (replaces the neighbour rule of agenda (h)):* one function serves both `advance_after` and `reconcile_selection` (design review F7: the neighbour is chosen from the nav order **as it was when the row was last selected** — `select()` snapshots `(root, nav index)` — because `advance_after` runs after `apply_pile` has already moved the neighbours). Rule: the nearest surviving entry **below** the vanished one **within the same repo** (rows and groups; a hunk accept that leaves hunks keeps the cursor index clamped, unchanged), else the nearest **above** within the same repo — the repo's own name row is the last "above", so **accepting the last file lands on the repo row** and the right pane says `nothing pending in <name>`; only when the repo itself has left the nav (`hide_empty` on, or the scope hid it) the entry now at its former nav index, else the previous entry, else nothing. Never a wrap to the repo's first row; never a jump into another repo while this one is still listed. `advance_after_restore` goes through the same function.
   4. *Tests:* unit — `app_empty_root_is_listed_and_selectable`, `app_hide_empty_unlists_a_root_with_no_rows_but_keeps_a_flagged_one`, `app_accept_last_file_selects_the_repo_row`, `app_accept_middle_file_selects_the_row_below`, `app_accept_first_file_selects_the_row_below_not_above`, `app_hide_empty_accept_last_file_selects_the_entry_that_takes_its_place`, `app_reconcile_uses_the_same_neighbour_rule_as_advance` (an external commit removing several rows at once), `app_scope_and_hide_empty_are_independent`, `render_empty_root_row_is_dim_and_has_no_file_rows`, `render_hint_line_names_the_toggle_by_state`, config round-trip for `hide_empty_repos`; snapshots — `tui_accept_last_file_collapses_repo` is **renamed** `tui_accept_last_file_lands_on_the_repo_row` (its frame changes meaning), new `tui_nav_empty_repo_row` (three roots, one empty, selected) and `tui_hide_empty_toggle` (the same after `t`), `tui_empty_state` regenerates (three empty repos are now three nav rows), `tui_herdr_flag_only_root_listed` regenerates only if its frame moves; PTY — `pty_accept_last_file_lands_on_the_repo_row_then_t_hides_it` (accept the last row through the terminal, assert the repo row is highlighted and the pane says `nothing pending in`, press `t`, assert the repo is gone and the hint reads `t show empty`, press `t` again). `tui.md` "Keys" and the "Design pass inputs" table (a new "Nav listing" row) record the rule; the working agreement 6 look applies (the hold's root list and the nav's now show the same set).

3. **Focus-true tier 0 on the hint line (Design pass D2; ruling R3).** When `effective_focus() == Focus::Diff`, tier 0 opens `↑↓ scroll  ← back` instead of `↑↓ select  ⏎ open` (`back` is the keymap's own action; `←` its arrow spelling); `v select  y copy`, the overlay rows and `SELECT_NOTE` stay as they are. Regenerates the 24 diff-focused frames D2 lists (the cyan main border in the styles files identifies them); `render_hints_follow_the_selection` gains the focus case. The `tui.md` hint-line row says so.

4. **The hint line fits what it can and drops from the right, one at a time; `? help` and `q quit` never go (ruling R4 — the sponsor's own rule, replacing D1).** `hints()` keeps building every applicable hint, but the shrink rule becomes: try the full line; if it does not fit, remove hints **one at a time from the right end of a fixed drop order** until it does — `y copy`, `v select` (tier 3), `r refresh`, `Tab focus`, `w scope` (tier 2), `^A accept all`, `g jump`, `d ack`, `A accept file` (tier 1), then `n/p hunk`, then the accept phrase (tier 0's optional parts) — and **`? help  q quit` are always the last two hints on the line**, so a cut line still says where the rest is. The 70-column `NAV_MIN_COLS` gate on tiers 2–3 stays (below it the nav is gone and `Tab focus` is untrue).
