# Phase 2 Kickoff Prompt (operational artifact, not design)

Phase 2 of the lastcall phased program. Phase 1 closed on 2026-09-01 (PR #1, merged `692e43a`): the workspace, `just` targets, CI on both OSes, the config layer (`lastcall_engine::config`, every §6.1 key, injected `Env`), the herdr client behind the `herdr` feature, the mock server, and the deterministic fixture-repo builder (`lastcall_testkit::fixture_repo::FixtureRepo`) all exist. Nothing reviews anything yet. This phase builds the **review engine**: the private object store, the seen-tree ledger, the private-index scan, pending computation with hunks, the accept operations, git awareness (HEAD tracking, upstream annotation, notices), root discovery, draft roots, the watcher, crash safety, and a headless `lastcall status --json`. It closes Gate 2 (§8, Phase 2). Phase 3 puts a TUI on top of exactly the types you build here, so the library surface is the product.

**The spine of this phase is the seen-tree model (§6.2, §10 "Ledger baseline model") and invariants 1, 2, 3 and 5 (§2).** The baseline for every path is *content*: a git tree in a private store we own, plus per-path overrides. `pending(p) = diff(baseline(p), worktree(p))`, computed fresh on every scan and never stored (invariant 1: the ledger is recomputable from scratch; a restart costs a rescan). **HEAD is never consulted for correctness** — not for baselines, not for candidates, not for first sight after the first sight. An agent's commit changes no worktree bytes, so nothing leaves the pile (invariant 5, scenario B1); a branch switch over-shows and self-clears (B4); a content-preserving rebase re-flags nothing (B5). Git history is an **annotation layer** (§6.4): it can add a label, a group, or a notice, never remove a row. Every resolution failure — missing object, unparsable override, unreadable ledger, index lock held — falls to the next step and **over-shows** (invariant 2): the tool may show too much after a failure; it must never hide a change. Every accept is **compare-and-swap** against the rendered content hash, never a fresh read of disk (invariant 3, F3 in the spec's review history): an agent write between render and click yields a refusal, never a silently blessed change. If you find yourself reaching for `HEAD`, `git status`, or a re-read of the live file to decide what is pending or what to accept, stop — that is the bug the model was chosen to eliminate.

**The executable reference implementation is the Phase 0 shell harness** `scripts/harness/lc.sh` (151 lines) with `scenarios.sh` (46/46 green, `just harness`). It is the git plumbing of §6.1–6.5 as shell functions, and it surfaced four rules that are now in the frozen spec. Port it function by function; when your Rust disagrees with it, the harness is right until a test proves otherwise, and then the *spec* is what you cite in your report.

## Deliverables

1. **`git.rs` — the single spawn site.** Exactly one module spawns `git`; a gate grep proves it (`rg -n 'Command::new\("git"\)' crates/lastcall-engine/src` → one file). Two runners, both taking the injected `Env`:
   - `StoreGit` — every command against **our** store: `Command::new("git").current_dir(<root>)` (cwd **is** the root — the `text=auto` rule, §6.4) with `GIT_DIR=<store>`, `GIT_WORK_TREE=<root>`, `GIT_INDEX_FILE=<our index or a temp index>` set explicitly on every call, plus `-c core.excludesfile=<the user's effective core.excludesfile, if any>`.
   - `RepoGit` — read-only inspection of the **user's** repo: `git -C <root>` with `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` **removed** from the child env. Its command set is a closed allowlist enforced by a unit test over the runner's own API: `rev-parse`, `symbolic-ref`, `config --get`, `ls-files` (`-v`, `-u`, `--stage` forms only), `rev-list`, `merge-base`, `log --format`, `diff-tree`, `cat-file`, `for-each-ref`, `worktree list --porcelain`, `--version`. **Never** `status`, `diff`, `add`, `update-index`, `checkout`, `stash`, `gc`, or anything that can take the user's `index.lock` or write their repo — the user's index is theirs (skip-worktree bits are *read* from it, D6).
   - Both: `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, inherit the process env otherwise (so the user's real global config is honored in production), and overlay every `GIT_*` / `XDG_*` / `HOME` variable present in the injected `Env` (so tests set `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_CONFIG_NOSYSTEM=1` through `Env` and the engine's children see them). `Env` cannot be enumerated today (`env.rs` exposes `var`/`home`/`cwd` only): add `Env::vars() -> impl Iterator<Item = (&str, &str)>` (additive). **After** the overlay, both runners scrub `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_CEILING_DIRECTORIES`, `GIT_NAMESPACE`, `GIT_PREFIX`, `GIT_INDEX_VERSION` from the child (a git hook shell exports several of these; `GIT_OBJECT_DIRECTORY` alone would redirect the store's writes), and `StoreGit` then sets its three explicitly. `-z` on every path-producing command, with NUL-parsers for `diff-files -z` (`:<omode> <nmode> <ooid> <noid> <status>\0<path>\0`), `ls-files -z`, `ls-files --stage -z`, `ls-tree -z`, `diff-tree -z`, `cat-file --batch-check`. Paths are bytes (`Vec<u8>` / `OsStr`) end to end; JSON output renders them lossily and a non-UTF-8 path is reported pending with a notice and refuses accept in v1 (over-show; record it as an informational deferral in your report). Errors carry the argv, cwd, exit status and stderr (`GitError`, thiserror).

2. **`paths.rs` + `store.rs` — identity and the private object store (§6.1).** `RootId`/`ParentId` = the first 16 hex chars of SHA-256 (`sha2` crate) of the **canonicalized** absolute path (`fs::canonicalize`; on macOS `/tmp` → `/private/tmp`), recorded in `meta.json` / `ledger.json`; on open a recorded path that no longer canonicalizes to the same string is a different root (E4: first sight, plus a best-effort notice naming any sibling `repos/*/ledger.json` under the same parent whose recorded root no longer exists on disk). Layout exactly as §6.1: `<state>/roots/<parent-hash>/meta.json`, `repos/<repo-hash>/{ledger.json, store/, index, lock}`. The store is `git init -q --bare`; for git roots write `store/objects/info/alternates` = `git -C <root> rev-parse --path-format=absolute --git-path objects` (for a linked worktree this resolves to the common object dir — that is the D10 rule) and copy `core.autocrlf`, `core.eol`, `core.filemode`, `core.ignorecase` from the user's effective config into the store's config **at every open**, not only at init (the user may change them); at the same time copy the user's `info/attributes` (`RepoGit rev-parse --path-format=absolute --git-path info/attributes`, the common dir for linked worktrees) to `<store>/info/attributes`, or remove ours when theirs is absent — like `info/exclude`, it is invisible to the store otherwise and a `* text=auto` living only there makes every CRLF file churn. Draft roots: same store, no alternates, no key copy. Operations: `hash_path(rel) -> Oid` (`hash-object -w -- <rel>` from cwd=root; symlinks via `lstat` → `readlink` → `hash-object -w --stdin`, mode `120000`), `hash_bytes(bytes)` (`hash-object -w --stdin`, no `--path`: the bytes are already-normalized baseline content, used by accept-hunk), `cat_blob(oid) -> Vec<u8>`, `exists(oid)` via `cat-file --batch-check` (batchable), `ls_tree(tree) -> BTreeMap<path, (mode, oid)>` (`ls-tree -r -z`), `write_tree(entries)` (`update-index -z --index-info` into a **temp** index at the fixed path `<repo>/index.tmp` — unlinked on open and after use; `read-tree` replaces a stale one harmlessly — seeded by `read-tree <seen_tree>` or `read-tree --empty`, then `write-tree`; entries are `<mode> <oid>\t<path>\0`, removals `0 0000…0\t<path>\0`; without `-z` a path containing a newline is a `fatal: malformed index info`), `tree_of_disk()` for draft first sight (a temp index, `update-index --add -z --stdin` over the file list; never `git add`). **Never run `gc`, `prune`, `repack -d`, or `fsck --lost-found` in the store**: nothing in it is anchored by a ref, so pruning would delete the seen tree and every override blob. The store grows by one loose object per scanned version of each changed file; that is accepted for v1 and goes in your report as an informational deferral (hardening shape: `refs/lastcall/seen` + an overrides tree ref, then `gc` becomes safe). **Git skips the physical write when an object already exists through the alternate**, so `hash-object -w` and `write-tree` leave `HEAD^{tree}`, every subtree, and every unchanged blob living only in the *user's* objects dir, unanchored by us — deliverable 3 has the rule for when they vanish. Clean filters run inside `hash-object -w` with `GIT_DIR=<store>` (a `filter=lfs` attribute executes `git-lfs clean`, which writes under `<store>/lfs/` or fails when git-lfs is missing — deliverable 5's `Unhashable`); note it in `engine.md` and the report as an informational deferral.

3. **`ledger.rs` — schema v1.0 (§6.2 verbatim), fail-open loading, atomic writes, locking.** Serde types matching the JSON in §6.2 field for field (`schema_version: "1.0"`, `root`, `kind`, `seen_tree`, `seen_at { head_commit, branch, at }`, `overrides { <path>: { blob?, mode?, flag?, updated_at } }`), `deny_unknown_fields` **off** (a newer minor version must still load; unknown fields are dropped on rewrite — say so in a comment). Loading rules, each a unit test: missing file → first sight; unparsable file or unknown `schema_version` major → the file is **moved aside** to `ledger.json.unreadable-<unix-secs>-<n>` (never overwritten, never deleted; `<n>` disambiguates within a second) and the root opens with `seen_tree = null`, `seen_at.head_commit = null` — every path pending, per invariant 2. This is **not** first sight: first sight at the current HEAD would hide everything committed since the original first sight (B1 in reverse). One notice naming the moved-aside file; the user's accept-all re-establishes a tree; an override with an unparsable shape → that path resolves to the tree (E2), one notice, the rest of the ledger intact. Saving: serialize to `ledger.json.tmp` in the same directory, `sync_all`, `rename` (§6.1 write ordering: objects first, then the ledger — accept-hunk's blob is written before the ledger references it). Every read-modify-write of the ledger holds `<repo>/lock` via `std::fs::File::try_lock` (stable since 1.89; no `nix` in product crates) with a bounded retry (e.g. 20 × 50 ms; after that the operation **errors** — never write unlocked), re-reads the file under the lock, applies, writes, renames — so `lastcall status` and a future TUI on the same root cannot lose each other's writes. `seen_at.at` and `updated_at` come from an injected `Clock` trait (production: `SystemTime`; tests: fixed), so ledger round-trip tests are byte-stable. **Baseline resolution** is one function, `baseline(path) -> Baseline { Present{oid, mode} | Absent | Empty }` implementing §6.2's order (override blob → override `null` = Absent → tree entry → Empty) and verifying `exists(oid)` before trusting any override or tree oid — a missing object steps to the next rule and records a notice (E2/E3). Unit-test the order with a fake store. **The seen tree itself is unanchored** (deliverable 2): `HEAD^{tree}` at first sight, and any fold result equal to a tree the user's repo already has, physically live only in the user's objects dir; a history rewrite followed by reflog expiry (`gc.reflogExpireUnreachable`, 30 d) and auto-gc deletes them — verified: `commit --amend`, `reflog expire --expire=now --all`, `gc --prune=now` → `cat-file -e <seen_tree>` fails and `read-tree <seen_tree>` is `fatal: failed to unpack tree object`. Rule: on open and immediately before every fold, `exists(seen_tree)`; a missing seen tree is treated as `null` for the session (every path pending; notice "seen tree <sha> missing from <objects dir> (pruned?) — everything re-flagged") and the next fold seeds from `read-tree --empty`; the ledger file is left untouched until that fold writes a tree that exists. Report it as a §11 addition: unanchored seen *trees*, not only loose blobs.

4. **`index.rs` — the private index, a cache and never truth (§6.5).** `seed(seen_tree)` = `read-tree <tree>` (or `--empty`) into `<repo>/index`, **then** record the tree it was seeded from in `<repo>/index.tree` (tmp + rename; the reverse order makes a half-written index look fresh); on open, if `index.tree` ≠ `ledger.seen_tree` or the index is missing/unreadable, reseed. `refresh()` = `update-index -q --refresh --ignore-submodules` (exit status ignored: it is non-zero when files differ); if git reports `index.lock` held (another lastcall process — `read-tree` takes the same lock, so the reseed path retries identically), retry three times with 50 ms backoff, then **scan without refresh** — `diff-files` still lists every candidate, at worst over-reporting, so the scan stays correct. `diff_files() -> Vec<(path, status, old_mode, old_oid)>` (`diff-files -z --ignore-submodules=all`). `others()` = `ls-files -c core.ignorecase=false --others -z` (the `-c` is deliverable 5's case rule) with `--exclude-standard` for git roots plus `--exclude-from=$(RepoGit rev-parse --path-format=absolute --git-path info/exclude)` when that file exists (the common dir for linked worktrees — `<git-dir>/info/exclude` is the wrong file there; the store's own `info/exclude` is empty, so `--exclude-standard` alone misses the user's), no excludes for draft roots. Entries ending in `/` are nested repositories (D9) — never candidates of this root; they are reported to root discovery. A test deletes `index` and `index.tree` between two scans and asserts identical piles (the index is a cache).

5. **`scan.rs` — candidates → pending rows.** Port `lc_candidates` + `lc_pending_p` + `lc_pile`: candidates = `diff_files` paths ∪ `others` ∪ every override path ∪ (case-insensitive roots only) index entries whose exact name is absent from their directory, minus paths tagged `S` in the **user's** index (`RepoGit ls-files -v -z`, D6; git clears the bit in memory for a file present on disk, so this filter can only ever suppress absent paths), minus **`others` entries** that lie under a nested repo (`dir/` entries) or under a draft root owned by another root. Paths that come from `diff_files`, an override, or the case rule are **never** excluded: content in the seen tree is this root's regardless of which root now owns the directory (an agent that `git init`s inside `vendor/lib` and rewrites a tracked file there must still show in the outer root — verified that git's own `status` shows it; over-show beats hide). **Case rule (D4):** at open, probe whether the root's filesystem is case-insensitive (`lstat` of the root path with its last component case-toggled resolving to the same device+inode; a name without letters → the platform default); on such a root the current-side existence of an index or override path is decided by a **byte-exact `readdir` of its parent directory** (one listing per directory per scan, cached), never by `lstat` alone — after `mv f.txt F.txt`, `lstat("f.txt")` still succeeds and D4 requires the deletion row: `f.txt` deleted + `F.txt` added for both root kinds, paired by D5 rename detection when it runs (the D4 tests assert the two rows, not the pairing). For each candidate: `current = lstat` → `Absent` | `Unhashable(reason)` | `{oid: hash_path, mode}`. `Unhashable` covers a directory where a file was (`hash-object` exits 128 "Unable to hash"), EACCES, and a failing clean filter; an `Unhashable` candidate is **always** a pending row (`change: typechange` for a directory, else `unreadable`; `current: null`, no hunks, a row notice) and accept is refused for it — never drop a candidate because hashing failed. `mode` is `120000` for symlinks, `100755` when executable **and** the store's `core.filemode` is not `false`, else `100644`. `baseline` from deliverable 3. A row is pending iff `baseline != current` by oid **or** by mode (D1: a mode-only change is a row with one synthetic hunk `mode 100644 → 100755`). Row fields: `path`, `change: modified|added|deleted|mode|typechange`, `baseline: Option<{oid, mode}>`, `current: Option<{oid, mode}>`, `added`/`deleted` line counts, `hunks` (deliverable 6), `annotation` (deliverable 9), `conflicted` (path listed by the user's `ls-files -u`), `collapsed: Option<glob|binary|size>` (D7/D8: `collapsed_globs` match, git's binary heuristic — a NUL in the first 8000 bytes of either side — or either side larger than `collapse_size_bytes`; collapsed rows carry counts but no hunks), `flag` (from the override), `rename: Option<{ from | to, similarity }>` (D5: only when the pile has both deletions and additions — a temp index that is a **copy of the refreshed private index** (a `read-tree` seed has no stat data and `diff -M` would re-hash every tracked file), `git add -N -- <added paths>` under `StoreGit`, then `diff -M -z --name-status`; pairing is presentation, the ledger stores delete + add; the added row carries `from`, the deleted row carries `to`). Rows sorted by path bytes. **Every scan re-hashes only candidates**, never the whole tree, and hashes them in one `hash-object -w --stdin-paths` call (`hash_paths(&[rel])`; a path containing a newline falls back to a single call) — the stat cache makes the common case a stat-only pass (a debug counter of `hash-object` calls per scan, asserted in one test: a second scan with no changes issues zero hashes).

6. **`hunks.rs` — the diff model.** Line diff of two byte buffers (the `similar` crate, `TextDiff::from_lines` over `&[u8]`, unified hunks at **context 3** so hunk boundaries match `git diff`'s), never requiring UTF-8. `Hunk { index, old_range, new_range, lines: Vec<(tag, bytes)> }`; `counts(a, b) -> (added, deleted)` must equal `git diff --numstat <a> <b>` — assert it in the D3 test (CRLF, `text=auto`: 1/1, not 3/3, because both blobs come from the store, already normalized) and on three more rows. `apply_hunks(baseline, hunks, selected: &[usize]) -> Vec<u8>` splices exactly the selected hunks' change lines into the baseline in **one pass** (hunk ranges are relative to the original baseline; applying one at a time would leave the next hunk's offsets stale). **Property tests** (proptest, `cases: 1000`, in the unit tier, seed and count printed in the report) over random `(baseline, current)` line sequences built from **unique** lines (`line-<n>`, so the LCS is unambiguous and a diff-library tie-break cannot fail a correct implementation) with random insert/delete/replace edits, files with and without a trailing newline, and an empty side: (1) for every hunk `i`, with `b' = apply_hunks(baseline, hunks, &[i])`, the multiset of tagged change lines in `diff(b', current)` equals the original multiset minus hunk `i`'s change lines (context lines excluded, since neighbours regroup) — "never resurrects the accepted hunk, never drops an unaccepted one"; (2) every subset, in particular the full set, yields the oracle built directly from the edit script, and the full set yields `current` byte-for-byte. Commit any `proptest-regressions/` files that appear.

7. **`ops.rs` — accept operations, all CAS (§6.3), plus compaction.** Inputs are **rendered tokens** taken from a scan's rows, never fresh reads: `Rendered { path, oid: Option<Oid>, mode: Option<Mode>, baseline: Option<Oid> }` — `baseline` pins the baseline the hunks were computed against, so two processes on one root cannot splice a hunk at stale offsets (P1 accepts hunk 1, P2 clicks hunk 2 rendered against the old baseline: P2's live CAS passes but its baseline CAS refuses).
   - `accept_file(rendered)`: re-hash the live path with `hash_path` (`-w`; "in the store" means resolvable through the store — git skips the physical write when the alternate already has the object); if `(oid, mode)` ≠ rendered → `Refused::Moved { live }` and no ledger write (A6). `accept_group(rendered rows)` (C2 "accept-group → []") = `accept_file` over each row, collecting refusals, one ledger write. Else override `{blob: oid, mode}`; if that equals the seen-tree entry, remove the override instead — keeping any `flag` (§6.2 clean-up rule). `seen_head` is untouched.
   - `accept_deletion(rendered with oid None)`: refused if `lstat` succeeds; else override `{blob: null}` (A7).
   - `accept_hunk(rendered, hunk_index)`: CAS as accept_file **plus** `baseline(path).oid == rendered.baseline` (else `Refused::BaselineMoved`); `b' = apply_hunks(baseline_bytes, hunks, &[i])`; `oid' = hash_bytes(b')` (written first), then override `{blob: oid', mode: rendered.mode}` (A3). Baseline `Absent`/`Empty` → the baseline bytes are empty.
   - `accept_all(snapshot: &Pile)`: one mechanism for accept-all **and** compaction — `fold(snapshot)`: temp index = `read-tree <seen_tree>` (or empty) ⊕ every override (`blob` → entry with the override's mode; `null` → removal) ⊕ every row of the snapshot (rendered `oid`/`mode`; `Absent` → removal); `write-tree`; then `seen_tree = new`, every override loses its `blob`/`mode` (a flag-only override stays; an override with neither is deleted), and for **accept-all only** `seen_at = { head_commit: HEAD, branch, at: now }`; reseed the index. A5: a row whose disk content moved after the snapshot is folded at its *rendered* oid, so the next scan shows only the post-confirm delta. Existing overrides on paths that are not pending are folded in too — otherwise clearing them would re-flag content the user already accepted (this is why the harness's `lc_accept_all` iterates override paths as candidates).
   - `compact()` = `fold(&Pile::empty())` with `seen_at` **unchanged** (§6.2: "invisible to the user and changes no baseline"; moving `seen_head` would un-group still-pending upstream rows). Triggered automatically after any ledger write when overrides carrying a `blob` exceed `EngineOptions::compaction_threshold` (default 500, injectable; E5 tests with 10). Pile before == pile after, asserted.
   - `flag(path, note)` / `unflag(path)`: set/clear `flag` on the override without touching `blob` (A8's Phase 2 slice: schema + retention through accept-all; export is Phase 7). Restore is **Phase 7**: do not implement it.
   - **Fault injection for E1:** every op takes a `&dyn FaultInjector` with `fn at(&self, point: FaultPoint)`; production passes `NoFault`; points are `AfterObjectWrite` and `AfterLedgerTmpWrite`. The testkit's implementation SIGKILLs the current process (`nix::sys::signal::kill(getpid(), SIGKILL)` — testkit may use `nix`; the engine may not). This is the one test seam in product code; name it in a comment.

8. **`headstate.rs` — HEAD, branch, in-progress state, notices (§6.4 "HEAD tracking", "In-progress operations").** `inspect(root) -> HeadState { head: Option<Oid>, branch: Option<String>, detached, in_progress: Option<Merge|Rebase|CherryPick|Revert>, merge_head: Option<Oid>, shallow }` from `rev-parse HEAD`, `symbolic-ref -q --short HEAD`, the presence of `MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD`/`rebase-merge/`/`rebase-apply/` under `rev-parse --git-dir` (the per-worktree dir, D10), `rev-parse --is-shallow-repository`. `transition(prev, next, last_reflog_line) -> Option<Notice>`: the last line of `<git-dir>/logs/HEAD` is a **hint for the text only**; classification by message prefix: `commit`/`commit (amend)`/`commit (merge)` → "committed on <branch> (N commits)" (N = `rev-list --count prev..next`); `checkout: moving from A to B` → "switched A → B (same commit)" or "switched A → B: N files differ from seen state" (N from the scan that follows, so the `Head` event is emitted after that scan); `rebase (finish)`/`rebase -i (finish)` → "rebased <branch> onto <onto>"; `reset: moving to X` → "reset: moving to X"; `pull:`/`merge` → "merged …"; unknown → "HEAD moved: <message>". Notices are suppressed while `in_progress` is set and emitted once when it clears. A wrong notice text is a cosmetic bug; a notice that changes any baseline or row is a spec violation. Unit-test the classifier on literal reflog lines; integration-test B1–B3, B7 against real reflogs.

9. **`upstream.rs` — the annotation classifier, harness-verified (§6.4 "Upstream annotation").** Port `lc_upstream_paths` + the per-path rule in `lc_pile` exactly: heads = `HEAD` + `MERGE_HEAD` when present; per head, range = `seen_head..head` if `merge-base --is-ancestor seen_head head`, else `merge-base(seen_head, head)..head`, and no merge-base → no annotation (C7); `seen_head` is `ledger.seen_at.head_commit`, `None` → no annotation. Per commit: upstream iff remote-reachable **and** neither author nor committer email equals the user's `user.email` (`RepoGit config --get user.email`; unset → the identity test passes vacuously, which is the §11 heuristic); local merge (≥2 parents, not upstream) → its `diff-tree --cc` paths go to **M**; other local commits → **L**; upstream → **U**. Per pending row: in U∖(L∪M) and `current.oid` equals the path's blob at some head (`rev-parse -q --verify <head>:<path>`) → `upstream`; in U and (in L∪M, or differs from every head) → `mixed`; else none. **Cost is bounded per head, not per commit** (`seen_head` moves only at accept-all, so a month without one is thousands of commits per 750 ms scan otherwise): `rev-list <range> --not --remotes` once per head gives the not-remote set, and one `log --cc --name-only -z --format='%x01%H %P %ae %ce' <range>` per head gives every commit's parents, identities, and touched paths (a merge lists only its `--cc` paths, matching `diff-tree --cc`; verified). Memoize the classification on `(seen_head, head, merge_head)` and recompute only when `HeadState` changes; per-row work is then a lookup plus the `rev-parse <head>:<path>` blob compare (batch those through `cat-file --batch-check` on `<head>:<path>` lines). Detached HEAD with no upstream, shallow, or zero remotes → no annotation, individual rows. Group rows are derived: `groups = [{kind: upstream, paths}]` for the rows tagged `upstream` (§6.7 renders them as "upstream · N files"; the rows stay in `pending` too — the JSON is lossless). Tests: C1–C8, B5, B9 (an agent's own pushed commit stays an individual row — the identity test is what makes that true).

10. **`roots.rs` — discovery and rescan (§6.5 last paragraph, §6.4 "Nested git"/"Worktrees").** For each resolved parent dir P: if P is inside a git repo (`rev-parse --show-toplevel` succeeds from P) that repo is a root; otherwise every immediate child directory of P with a `.git` entry (directory **or** file — a linked worktree's `.git` is a file) is a git root. Draft roots: each `draft_dirs` entry that is absolute names a directory; a relative entry is a glob matched against directory paths relative to each parent dir **and** relative to each discovered git root (so `_drafts/**` matches `<parent>/_drafts` and `<repo>/_drafts`; the matched directory is the root; a trailing `/**` is accepted and ignored). A draft root inside a git root: the git root's `others` entries under it belong to the draft root, but tracked content there stays the git root's per deliverable 5 (F1's `_drafts/` is gitignored in the scenario; the rule must not depend on that). Nested repositories reported by `others()` (D9) become git roots with `badge: nested_in`. Linked worktrees: `rev-parse --git-dir` ≠ `--git-common-dir` → `badge: worktree_of <main worktree>` (from `worktree list --porcelain`'s first entry), HEAD watching under the per-worktree git dir (deliverable 11). Parent association for state layout: a root discovered under configured parent P — directly, as a nested repo, or as a linked worktree — uses the configured P that contains it; a root outside every configured parent (ad-hoc cwd, a worktree elsewhere) uses its own parent directory. A draft root's `seen_head` is `null`. A root whose directory disappears from disk while watched is reported as `RootsChanged { removed }` (its ledger kept), never as N deletion rows. `rescan()` runs at startup and on `EngineTimings::rescan` (default 30 s, injectable) and emits `RootsChanged { added, removed }`; roots keep their ledgers when removed from the watch set (never delete state).

11. **`watcher.rs` — `notify` + HEAD watching + polls (§6.5), invariant 9.** One `notify::RecommendedWatcher`; every root watched recursively, events filtered by `ignore_globs` (`globset`) — and **`ignore_globs` scopes the watcher only**: the scan enumerates from the private index regardless, so an edit under `vendor/` is discovered on the next scan (test: with `vendor/**` ignored, an edit to a tracked `vendor/x` appears on a manual rescan and after the next poll). Per root, the git-dir allowlist watched explicitly (§6.5 verbatim): `HEAD`, `index`, `ORIG_HEAD`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `packed-refs`, `refs/` (recursive), `rebase-merge/`, `rebase-apply/`, under `--git-dir` **and** `--git-common-dir` when they differ; FSEvents is recursive by nature, so filter events to that allowlist rather than trusting the watch granularity. Events only ever **schedule**: a root scan (trailing-edge debounce, `EngineTimings::debounce` = 750 ms, hardcoded in production per G0 Q6, injectable in tests) or a HEAD inspection; a HEAD poll every `head_poll` (10 s) and the rescan timer are the invariant-9 backstops; a watcher error/overflow schedules a full scan of every root. Output is `tokio::sync::mpsc<EngineEvent>`: `Pile { root, pile }` after every scan, `Head { root, from, to, branch, notice }`, `RootsChanged`, `Notice { root: Option, text }`. Subprocess work runs on `spawn_blocking` (or a dedicated thread), never on a runtime worker. Gate item 4 ("a commit with no other file activity triggers re-inspection within the poll interval") is a real-time integration test with `head_poll = 250 ms`, deadline 5 s, asserting a `Head` event with `notice` starting "committed on main".

## Traps (each is a verified failure; design them out)

- **`hash-object` must run with cwd = root and a root-relative path.** From any other cwd, `text=auto` is not applied and a CRLF file diffs as whole-file churn (harness D3: 3/3 instead of 1/1). `StoreGit` sets `current_dir(root)` unconditionally.
- **`hash-object -- <symlink>` follows the link** (verified). `lstat` first; link text via `--stdin`.
- **`ls-files --others` lists nested repos as `dir/`**, never their contents; it never lists `.git`. Treat a trailing `/` as "another root".
- **The user's `info/exclude` is invisible to our store's `--exclude-standard`**; pass `--exclude-from`. Their global `core.excludesfile` is honored automatically in production (we inherit their config) and nulled in tests (`GIT_CONFIG_GLOBAL=/dev/null` through `Env`).
- **Skip-worktree lives in the user's index**, not ours (D6). Without the `S` filter every sparse-excluded file is a false pending deletion.
- **`MERGE_HEAD` is a classification head and `--cc` paths are mixed** (C4/C5). A merge in progress has no merge commit yet; the classifier must not wait for one.
- **Never touch the user's index.** `git status`, `git diff` (porcelain) and `git add` on their repo can take `index.lock` and rewrite it; `RepoGit`'s allowlist test is the guard. `GIT_OPTIONAL_LOCKS=0` everywhere as belt and braces.
- **`GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` leak both ways.** Set all three explicitly for store commands; remove all three for user-repo commands; never rely on inheritance (the sponsor may run lastcall from inside a git hook or an agent shell that exports them).
- **Our index is a cache.** Reseed whenever `index.tree` ≠ `seen_tree`; a deleted index must produce an identical pile.
- **`index.lock` contention** between two lastcall processes: retry, then scan unrefreshed (over-show), never fail the scan.
- **Nothing in the store is ref-anchored.** No `gc`/`prune`/`repack -d` on it, ever. Plumbing commands never trigger auto-gc; `git commit`/`merge` would, and we never run them.
- **`write-tree` needs every blob present.** Draft first sight must write the blobs (temp index via `update-index --add`), not just list paths.
- **Compaction must not move `seen_head`**; accept-all does.
- **Accept-all folds existing overrides, not only pending rows** — otherwise clearing overrides re-flags accepted content.
- **`similar` hunks at context 3** so the TUI's hunks match `git diff`; the property test compares change lines, not context.
- **`FixtureRepo` uses env identity for its own commits; the classifier reads `user.email` from config.** Set the local config key in `new()` or B9/C1–C8 misclassify.
- **`notify` on macOS coalesces and may deliver a parent-directory event**; never derive "which file changed" from an event — it only schedules a scan of the root (invariant 9).
- **libtest swallows output of passing tests**: skips (D4 on a case-sensitive filesystem; anything else you must skip) are written with `stderr().write_all` and named in the report.
- **`git add -A` / `git add .` are denied** in your shell; stage explicitly. `git push` never. Worktree and `scripts/harness/work/` and `z_ignore/` are gitignored and not yours.
- **Git never writes an object the alternate already has.** "In the store" means "resolvable through the store"; the seen tree and every unchanged blob live in the user's objects dir and can be pruned. `exists()` before trusting, `null` on a missing seen tree (deliverable 3).
- **Only `others` entries are excluded for nested repos and draft roots.** A `diff_files` or override path under them is still this root's row (deliverable 5) — dropping it hides a tracked edit.
- **A hash failure is a row, not a skip.** Directory-where-a-file-was, EACCES, and a failing clean filter are `Unhashable` rows (deliverable 5).
- **Case-insensitive roots need a byte-exact `readdir`** for the deletion side of D4 and `-c core.ignorecase=false` on `ls-files --others` for the addition side; the store's copied `core.ignorecase` would otherwise fold `F.txt` into `f.txt` and show nothing.
- **First sight writes state from a "read-only" command.** `lastcall status` on a never-seen root creates the ledger, by design (§6.2). Say so in `engine.md`.
