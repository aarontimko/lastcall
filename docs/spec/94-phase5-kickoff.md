## Deliverables

1. **Entry obligation — open/scan cost (engine; worker 5a; first).**
   - (a) **Bounded parallel root open.** `rescan` opens newly discovered roots on a scoped thread pool (`std::thread::scope`, bound `EngineOptions.parallelism: usize`, default `min(available_parallelism(), 8)`, floor 1; the integration golden is run at 1 and 8 through an `LASTCALL_PARALLELISM` env override read in the binary only); the parent dir's `meta.json` write (`if !meta.exists()`) happens serially **before** the pool; results and notices are collected and applied in path order so `Engine` state and `status --json` are byte-identical to the serial result. Per-root failures stay per-root (an `Err` root does not fail the others, as today). Hold no engine lock across the pool: `open_root(&self, ..)` already borrows immutably.
   - (b) **Bounded parallel scan.** `scan_all` runs the per-root scan on the same pool. The per-root worker is **not** pure — it is `scan_root(&mut RootState, &Store, &ScanInputs) -> ScanOutcome { pile, nested_changed, notices }`, run over `roots.values_mut()` inside the scope (each root's state is borrowed by exactly one thread; the ledger reload, classifier cache and `last_pile` update stay inside it); the serial apply step iterates outcomes in path order, assigns `scan_seq`, appends notices and ORs `nested_changed`. `scan(&mut self, root)` for one root keeps its signature and behaviour (it calls `scan_root` then the apply step for one root). The nested-repo passes stay serial between passes. `EngineEvent::Pile { seq }` ordering guarantees (§10 Phase 4, "engine-global") are unchanged: `scan_seq` is written in the apply step only.
   - (c) **Per-root call list collapsed.** One `config --list -z` of the **user repo** per root, parsed once, replaces the reads of `core.excludesfile`, the four `COPIED_CONFIG_KEYS`, `user.email` and `remote.origin.url` (multi-valued keys: last wins, as `--get` does; the store-side `core.filemode` read-back at `store.rs:183` **stays**, it reports the store's effective value); one `config --list -z` of the private store decides which `set`/`unset` calls are needed (skip when the value already matches). `headstate::inspect` goes from six spawns to four: one `rev-parse --path-format=absolute --git-dir --git-common-dir --is-shallow-repository` (three infallible flags, outputs paired by position) plus `symbolic-ref -q --short HEAD` and the two `-q --verify` calls, which must stay separate because their non-zero exit is the signal; fold `git_path objects|info/attributes|info/exclude` into `--git-path …` flags of the batched call. The `RepoGit` allowlist widens by exactly one shape, `config --list -z` (`rev-parse` already takes any args), documented in `engine.md` "The two git runners" (ruling item 6). Expect ≤ 10 spawns per root at open and ≤ 10 per scan (inspect runs per scan); report before/after counts for both, they are not the gate.
   - (d) **Bench.** `just bench` S1 re-run before and after on the same machine, plus a new scenario **S1h** in `crates/lastcall/tests/test_bench.rs` = **50 roots × 80 files = 4,000 rows** with S1's fixture generator (S1 is 100 × 40; "S1 at 50 roots" would be 2,000 rows — the gate's absolute target is 4,000). `bench.md` gains an "after" table per scenario (before columns kept), the S1h table, and one paragraph on what changed. Print `BENCH S1h …` lines like the others.
   - (e) **Tests, by tier.** *Engine unit:* a fixed-pool determinism test comparing `scan_all` outputs (piles, notices, `scan_seq` order) at parallelism 1 vs 4 over ≥ 6 fixture roots; one unopenable root under parallel open leaves the others open; the `config --list -z` parser (empty values, `=` inside values, `\n` inside values, repeated keys); the batched `rev-parse` parser on a detached HEAD and on a linked worktree. *Integration:* `test_integration_status_golden` run at `LASTCALL_PARALLELISM=1` and `=8`, byte-identical. The existing scenario suites are the regression net. No git subprocess enters the binary crate's unit tier.
2. **N-instance hardening (engine; worker 5a; ruling item 2).** Amendment v1.2 already built the ledger side (see "Entry preconditions" 3): lock per root, unconditional re-read under the lock, replay of the staged accepts. Phase 5 adds only what is missing. (a) The **scan's temp index** becomes per-process: `index.<pid>.tmp` under the root's store (the §11 entry), created lazily, removed on `Engine` drop; stale `index.*.tmp` older than one hour are removed at `Store::open` (no liveness probe — no new dependency; see Traps); on Windows never delete. (b) `LOCK_RETRIES` 20 → 40 (2 s at the 50 ms backoff). (c) `LedgerError::LockBusy` surfaces in the TUI as the status line `ledger busy in <root> — try again` with the row still pending — it stays an `Err` on the `Local::Accepted` path, **not** a `Refused` variant (every `Refused` carries a row path and renders per row). (d) The **persistent private index** (`<store>/index`, `index.tree`) stays shared (rec; ruling item 2 alt is per-process copies): prove it with a test — two `Engine`s over one temp root scanning concurrently (a `std::thread::scope` pair) → both scans succeed and agree, `run_with_lock_retry` absorbing git's `index.lock`; if the retry budget is insufficient, raise it and report the numbers. Tests (engine unit, short backoffs via `acquire_with(paths, 2, 10 ms)` — no sleep over 50 ms): two engines accept different files on one root → both accepts persist after both reopen; a lock held by the test → `LockBusy` after the retries; the concurrent-scan pair; stale-index cleanup with a fabricated dead pid.
3. **Amendment A3 — relaxed hunk CAS (engine; worker 5a).** `accept_hunk` (`ops.rs:409–480`) no longer calls `cas_live` (`:292–315`); it keeps the baseline CAS (`BaselineMoved`), `NoSuchHunk`, and the deletion route (`rendered.oid.is_none()` → `accept_file`). Today both branches take the **mode from `live.mode`** — after the change the mode is **`rendered.mode`** (`Rendered` carries it, `:57–66`); never re-hash or re-stat the live file inside a hunk accept (a live read is exactly what A3 forbids). The override stays `hunks::apply_hunks(base_bytes, rendered_hunks, [k])` over the rendered baseline: baseline plus the accepted hunk, nothing the user did not see. `Refused::Moved` remains for file/root/all accepts (A6 stays CAS). The status text for hunk accepts is unchanged. **Two proptests** in the unit tier on the private-store path (`ops.rs:1079` style, `TestRunner`, `RootKind::Draft`, no git), both generating files with **≥ 2 hunks** (a one-hunk file makes hunk accept indistinguishable from file accept): (i) *unseen edit survives* — accept hunk k after an edit elsewhere in the file: the next render's hunk set equals the rendered set minus k, re-diffed against the new override (not a whole-file equality), and the other edit is still pending; (ii) *in-place rewrite shows X→Y* — accept hunk X, rewrite X's lines to Y on disk: the next render shows one pending hunk whose old side is X's new lines and whose new side is Y. Plus the e2e regression: `tui_accept_refused` keeps using `AcceptFile`. The §6.3 row is NOT yours to edit; Amendment v1.5 (PROPOSED, `00-spec.md`) already carries the replacement sentence.
4. **The herdr task in the TUI (worker 5b).** `commands/tui.rs`: after `Engine::open`, resolve `[herdr] mode` (`off` → no task; `auto` → discovery failure is silent standalone; `on` → discovery failure is a visible standalone notice), `discover(env, pinned, probe)` → `Client::spawn(transport, ClientTimings::default(), ClientOptions { reconnect: true })` exactly as `hello_herdr.rs` does, and pass `(ClientHandle, rx)` into `run::run` as `Option<HerdrLink>`. `run.rs` gains a fourth `select!` arm over `rx` that maps `HerdrEvent` → `Action::Herdr(HerdrUpdate)` where `HerdrUpdate` is a **TUI-side, socket-free** enum (`Connected { version, protocol }`, `Standalone { reason }`, `Reconnecting`, `Roots(BTreeMap<PathBuf, RootAgents>)`, `Toast(Result<ToastShown, String>)`, `Focused(Result<(), String>)`) — the reducer never sees `Cache`, `PaneInfo` or the handle. The mapping (a pure function `herdr::derive(cache: &Cache, roots: &[RootMeta]) -> BTreeMap<PathBuf, RootAgents>` in `crates/lastcall/src/tui/herdr.rs`, unit-tested with hand-built caches) implements §6.6 association: walk each agent-bearing pane's `foreground_cwd` (fallback `cwd`) up to the deepest known root; unresolvable panes are ignored; per root `RootAgents { status: AgentStatus (max-attention rollup, priority blocked > done > working > idle > unknown), agents: u32, pane: Option<String> (the single agent's public pane id; the max-attention agent's when several) }`. Re-derive on `PaneAssociation`, `Resync`, `AgentStatusChanged`, `Connected` and on `Local::Roots` (roots changed under a live cache). `Disconnected` → `Reconnecting`; `Standalone` → `Standalone`. Quit order: `handle.shutdown()` before the watcher stops (bounded like the watcher's own timeout). Effects out of the reducer: `Effect::Focus(pane_id)` → `agent.focus` request on a one-shot connection (a new `wire::AGENT_FOCUS` const + `AgentTarget` params type + a `ClientHandle::focus(pane_id)` or a free function over the transport, whichever `hello_herdr` style fits; result → `HerdrUpdate::Focused`); `Effect::Toast(ToastRequest)` → deliverable 6.
5. **Reducer, render, input (worker 5b).** `App` gains `herdr: HerdrView { link: Link::{Off, Connected{version}, Reconnecting, Standalone{reason}}, roots: BTreeMap<PathBuf, RootFlag> }` where `RootFlag { status, agents, pane, ready: Option<Ready { acked: bool }> }`. **Rules:** a `done` rollup sets `ready` (`acked: false`) unless `ready` is already `Some` for this episode; an ack sets `acked: true` and leaves the dot dimmed while herdr still says `done`; any non-`done` rollup clears `ready` entirely (episode over) — so the next `done` re-alerts, but the same `done` never does. **Listing rule (§6.7):** a root appears in the nav when it has pending rows **or** an attention flag; attention = `ready` (any) or `blocked`. `working`/`idle`/`unknown` never list a root by themselves — they annotate roots already listed. **Nav root row:** the dot sits before the bold name: `⚑` bright for `ready` unacked, `⚑` dim for acked-still-done, `●` red `blocked`, `●` yellow `working`, nothing for `idle`, `·` dim `unknown`; with `agents > 1` the count follows the dot (`⚑2`). A flag-only root (no pending rows) shows the branch line and one dim row `nothing pending · agent done` so `Enter` has somewhere to land (the diff pane says the same). **Header:** right of the counts, `herdr 0.8.2` dim when connected, `herdr ⟳` when reconnecting, `standalone` dim when off/absent, `standalone: <reason>` when `mode = on` failed — `HitMap::HeaderHerdr`, click shows the full reason in the status line for 30 s. **Keys (ruling item 4; rec):** `d` = ack the selected root's flag (root row, or any row of that root, either pane), `g` = jump to agent (`Effect::Focus` on `pane`; status `focused <agent> in herdr`, or the error text), `w` = toggle workspace scope (deliverable 8); all three in `DEFAULT_KEYMAP`, `[keys]`-rebindable, described in `Action::describe` and the help overlay. **Mouse:** click on the dot = ack; click on the name = select (as today). **Hint ladder:** `d ack` and `g jump` are tier-1 hints shown only while the selected root has a flag; `w scope` is tier 2 and shows only when a scope is active. **Snapshot scenes** (pure reducer, fixed `HerdrUpdate`s, two `assert_snapshot!` each): `tui_herdr_status_dots` (three roots: working, blocked, done), `tui_herdr_ready_ack_dims` (before/after `d`), `tui_herdr_flag_only_root_listed`, `tui_herdr_header_states` (connected / reconnecting / standalone reason), `tui_herdr_scope_notice` (deliverable 8). Parity tests: `d` vs click on the dot; `g` by key vs a hit on a `HitMap::RootJump` if you add a control (optional; a key is enough). A `HerdrUpdate` arriving during the accept-all modal or the help overlay must not close them.
6. **Toasts (worker 5b; ruling item 5).** Config: `[herdr] toast = true` (default; `HerdrConfig` is `deny_unknown_fields`, so the field is added with `#[serde(default)]`; `false` never calls `notification.show`). On a root's `ready` transition, the loop starts (or extends) a coalescing timer `TOAST_DELAY` = **7 s** (herdr's default `delay_seconds` 1 s + the `Finished` lifetime 5 s + 1 s margin — tied to herdr's defaults and documented as such); when it fires, **one** `notification.show` names every root that went ready in the window and is still unacked: title `lastcall: <name> ready for review` or `lastcall: <N> repos ready for review`, body the names joined by `, ` (title ≤ 80 chars, body ≤ 240, sanitised per §5.9). ## Traps (each is a verified failure elsewhere; design them out)

- **Parallel open that changes state.** Path-ordered insertion after the join; `scan_seq` assigned in the serial apply step only. The golden and the fixed-pool determinism test catch a reorder; a verifier will grep for `scan_seq` writes outside the apply step.
- **Holding the engine mutex across the pool or across `.await`** — the Phase 3/4 trap again. The pool lives inside one synchronous `rescan`/`scan_all` call under one `blocking`.
- **`config --list` semantics.** Values may contain `=` and newlines; `-z` framing is `key\nvalue\0`. Multi-valued keys repeat; take the last, as `config --get` does. An `includeIf` that git resolves for `--get` also resolves for `--list` (same process, same cwd) — do not "optimise" by reading the file yourself.
- **Batched `rev-parse` exits non-zero as a whole if any flag fails.** Only the three infallible flags go in one call; `-q --verify HEAD` / `MERGE_HEAD` stay separate because their exit code *is* the answer. Outputs pair by position; `--is-shallow-repository` prints `true`/`false` on its own line.
- **The bench in debug** measures nothing (Phase 4 trap): `just bench` builds release and skips otherwise. Fixture construction stays outside the timed region. Run S1 before and after on the same machine and paste both machine blocks.
- **Sick FSEvents on the sponsor's Mac** (§11): fixed on 2026-09-03 by restarting `fseventsd`, but the bench still records which path it measured, and the worktree-event test asserts on the herdr trigger, not on a file event.
- **Stale flags from the v0.8.2 replay.** Every connect replays up to 512 lifecycle events; the client coalesces them into snapshots, and the *snapshot* is truth. Derive `RootAgents` from the cache after `Resync`/`PaneAssociation`, never from individual replayed `Lifecycle` events, or the nav flashes flags for panes that died a day ago.
- **`done` re-alerting after ack.** The rule is per episode: `ready` clears only on a non-`done` rollup. A resync that re-reports the same `done` must not reset `acked`. The `tui_herdr_ready_ack_dims` second frame and a reducer test with a repeated `done` update pin it.
- **Toast timing.** A toast sent inside herdr's own [1 s, 6 s] busy window is refused; the 7 s delay plus one 5 s retry is the whole policy — no third request, ever (§5.9 "never retry-loop"). The mock's request count and paused-clock instants are the proof.
- **A toast that names a root the user already acked** — filter at fire time, not at schedule time.
- **The reducer touching a socket.** `app.rs` never imports `lastcall_engine::herdr`; `HerdrUpdate` is the boundary (grep in the gate).
- **`agent.focus` with the wrong target.** Pass the snapshot's `pane_id` verbatim (public id); a name would be ambiguous with two agents of the same kind. `agent_not_found` (pane died) is a status line, not a fatal.
- **Scope hiding pending work silently.** The scope notice with the hidden count is mandatory while a scope is active; the header counts follow the scope; `w` always restores the full view. A workspace whose `worktree.checkout_path` names a directory that is not a lastcall root (a repo outside `parent_dirs`) yields no scope, not an empty nav.
- **Two instances, one ledger — already solved, do not re-solve.** `Ops::commit` re-reads under the lock unconditionally and replays the staged accepts; a "re-read only if the file identity changed" shortcut is *weaker* (inode/mtime collide within one tick) and is not wanted. The two-engine test proves the existing path; the new work is the temp index and the shared persistent index (deliverable 2).
- **Stale-index cleanup must never delete a live process's file.** Without a liveness probe dependency, delete only `index.*.tmp` older than one hour; on Windows never delete. Report which rule you built.
- **`herdr server stop` semantics in the G6 test** — the harness that starts the pinned server owns its pid; restart on the **same** socket path or the client's discovery pins the old one. If the real-server tests cannot restart a server hermetically, say so and make G6 a mock test plus a manual recipe, reported as a deviation.
- **Fixture generated from master.** The consumed-surface fixture comes from the pinned release binary (`just herdr-fetch`), never from the reference clone; the provenance file names the tag.
- **Real tests that skip silently.** Each real-server test prints `SKIP <name>: LASTCALL_TEST_HERDR_BIN unset` exactly like the Phase 1 test; the CI integration job must show them running.
- **Tests touching the real herdr** (`~/.config/herdr/`, the default socket) — every test injects `Env` with its own `HOME`/`XDG_CONFIG_HOME`/`HERDR_SOCKET_PATH`; the discovery unit tests already show the pattern. **The reference clone `~/dev/git/herdr` is read-only; `git push` never; `git add -A` / `git add .` are denied; `z_ignore/` and other worktrees are not yours.**

## Rulings (presented after the design review; sponsor verdicts pending)

1. **Workspace scope rule and default.** Rec: scope by provenance first (`worktree.checkout_path` → that root plus its linked worktrees / nested repos), then by pane cwd containment, else none; default on (`[herdr] scope = "workspace"`), `w` toggles for the session, and a mandatory `scope: … · N repos hidden` notice — a lastcall pane in a one-repo workspace should show that repo (sponsor direction 2026-09-02), and the notice plus toggle keep invariant 2 ("never hides" is satisfied by one keypress and a visible count). Alt: no filtering, only ordering — the workspace's roots sort first and are marked; strictly never hides anything, but the sponsor's 50-clone parent dir still fills the nav in every workspace pane, which was the complaint. Two-way door (a rule and a default).
2. **Several lastcall processes over one state dir.** Rec: graceful N on top of what v1.2 already built (the per-root ledger lock with an unconditional re-read under it): a per-process scan temp index, the lock retry budget doubled to 2 s, `LockBusy` shown as a status line, and the **persistent private index kept shared** with a concurrent-scan test proving git's own `index.lock` retry absorbs it — item 1 makes one lastcall per workspace pane the normal setup, and the shared index writes the same refreshed content whoever wins. Alt: per-process copies of the persistent index too (`index.<pid>`, `index.tree.<pid>`, a `read-tree` seed per process) — airtight against any index contention, right if the concurrent-scan test shows retry exhaustion or if the store's index ever carries per-process content; costs a seed spawn per process per root and doubles the store's on-disk index state. A single-instance lock (`<state>/lastcall.lock`, second instance exits) is the other alt and fights item 1. Two-way door.
3. **Worker split.** Rec: three sequential workers (5a engine, 5b herdr UI, 5c real-server + workflow + docs), the Phase 4 shape, because the entry obligation is a self-contained engine change with its own instrument and the herdr UI is the bulk. Alt: two (5a engine, 5bc everything else) — one fewer merge and verifier pass; fine if the compat workflow is judged small, but 5c also holds the two real-server tests whose hermetic restart may need a deviation ruling, better isolated from the UI worker. Operational.
4. **Keys and the listing rule for annotations.** Rec: `d` ack, `g` jump-to-agent, `w` scope toggle (all unbound today, all `[keys]`-rebindable); click on the dot acks; attention = `done` (acked or not) or `blocked` lists a root with no pending rows, `working` only annotates. Alt: `Enter` on a flag-only root jumps (no `g`), and `blocked` does not list a root — fewer keys; but `Enter` already means open, and a blocked agent in a repo with nothing pending is exactly the case the user cannot see from the pile. Two-way door.
5. **Toast default, delay, retry.** Rec: `[herdr] toast = true`, `TOAST_DELAY` 7 s (herdr's default completion-toast delay 1 s + its 5 s lifetime + 1 s), one coalesced toast per window, and exactly one 5 s retry on `busy`/`rate_limited` — the review verified that herdr answers `busy` while *any* toast is on screen, so a 2 s delay would have been refused every time under the very setting our docs tell users to enable; the single retry is what frozen G7 ("delayed retry shows") describes and is not a retry loop (§5.9). Alt: default `false` and a plain one-shot at the `done` instant with no retry — simplest, but then the feature never fires for the one user who enabled `delivery = "herdr"`, and G7's expectation is unmet. Two-way door.
6. **Parallelism bound and the allowlist widening.** Rec: `EngineOptions.parallelism` default `min(available_parallelism, 8)` (no config key in v1; a binary-only `LASTCALL_PARALLELISM` env override exists for the golden), and the `RepoGit` allowlist widens by exactly one shape, `config --list -z` (`rev-parse` already accepts any args), documented in `engine.md`; git spawns are I/O-bound so 8 saturates a laptop without thrashing 100 roots' stores. Alt: a `[engine] parallelism` config key and no allowlist change (keep per-key `config --get`, parallelise only) — reaches the ≥ 4× S1 target by parallelism alone on an 8-core machine but not the 6 s S1h target on a 4-core one, and adds a knob nobody asked for. Two-way door.
7. **§3.5 circle-back after Phase 4 (ack semantics; accept-all confirmation threshold).** Rec: no change — local ack is what this phase builds (G0 Q3; herdr has no mark-seen API, re-verified at v0.8.2), and the >10-file confirm was used in the Gate 4 sponsor run without complaint. Alt: lower the confirm threshold to 5 or make it a config key — only if the sponsor found the modal too rare or too frequent in real use. Two-way door; recorded either way in §10.
8. **Claude Design pass timing and inputs.** Rec: after Phase 5 merges, on the real binary with herdr connected — the pass receives the Gate 4 sponsor-run rulings, this phase's five snapshot scenes, the header states and the scope notice, and its findings become the Phase 6 kickoff's first agenda item (post-build rulings, two-way doors). Alt: a sanctioned mid-phase checkpoint after 5b (the scenes exist, docs not yet written) — catches visual changes before 5c documents them, at the cost of a stall-shaped pause in the phase; right if the sponsor expects large layout changes rather than glyph/colour/copy changes. Operational.
9. **What lights the review-ready flag** (raised by the sponsor's workflow questions on 2026-09-03/04). Rec: the spec as frozen — the flag follows herdr's `done` label only, which herdr derives for a completion in a tab the user is not viewing (§5.7); in the sponsor's layout (lastcall in the parent-dir workspace, agents in repo workspaces) every unseen completion flags the parent instance and a completion the sponsor watched never does. Alt: flag on any transition out of `working`/`blocked` regardless of seen-tracking (a §6.6 amendment) — a "stopped" marker rather than an "unseen" marker; also lights the side-by-side pane and re-lights the parent for completions the user sat through. Two-way door; the orchestrator first recommended the Alt and reversed after the sponsor described the multi-workspace usage.
10. **Ack across several lastcall instances.** Rec: the ack stays per process in v1; `g` converges every instance through herdr's own seen flag; a §11 deferral with trigger "the sponsor finds a stale flag in a second instance annoying". Alt: persist the ack in the shared state dir (one small file per root store with the ack time, read on every re-derive) so every instance converges within seconds — a day in worker 5b plus a v1.5 storage line; right if the sponsor expects to ack from whichever pane is at hand. Two-way door.
