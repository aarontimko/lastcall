# Phase 3 Kickoff Prompt (operational artifact, not design)

**Rulings frozen 2026-09-02** (sponsor, verbatim "1 rec 2 rec 3 rec 4 rec 5 alt … 6 …"; recorded in `00-spec.md` §10): (1) bare `lastcall` launches the TUI; (2) a root is listed iff its pile has rows; (3) the first frame is the empty state with `scanning…` until piles arrive; (4) `Esc` never quits; (5) **a `[keys]` config table ships in this phase** (Amendment v1.3 proposed, deliverable 5); (6) the phase is built by **three sequential workers** ("Worker split" under Operational rules) because the sponsor's concern is context loss on the spec, not cost.

Phase 3 of the lastcall phased program. Phase 2 closed on 2026-09-02 (PR #2, merged `ba62907`): the review engine exists as a library — private store, seen-tree ledger, private-index scan, hunks, accept operations, git awareness, root discovery, draft roots, the watcher, crash safety — plus two headless surfaces, `lastcall status [--json]` (`status_version: 1`) and `lastcall watch`. Nothing has a screen yet. This phase puts the **read-only TUI** on top of exactly the types Phase 2 built: header, left nav (repos, branch lines, file rows with live counts), diff view with hunk navigation, watcher-driven live updates, mouse plus keyboard. **No accept, no restore, no flag, no editor** — those are Phases 4, 7 and 8. It closes Gate 3 (§8, Phase 3). Phase 4 adds the accept loop to this exact UI, so the state model and the widget boundaries are the product of this phase as much as the pixels are.

**The spine of this phase is invariant 9 (§2) applied to a screen: event streams are hints, engine piles are truth.** The TUI holds *no* review state of its own. Every row, count and hunk it draws comes from a `Pile` the engine published (`EngineEvent::Pile`) or returned from a scan the user asked for; the UI never diffs, never hashes, never reads a file, never spawns git (the single spawn site stays `git.rs`, gate grep). A screen is a pure function of `(App state, terminal size)`, and `App` is a pure function of the event sequence it was fed — which is what makes the whole UI testable through `ratatui::backend::TestBackend` with no terminal and drivable by the same `Action`s whether they came from a key or a mouse click. **Selection is by path, never by index**: a pile that arrives while the user is reading a hunk must not move what they are looking at (§6.7 "scroll position preserved best-effort"), and the engine may publish an unchanged pile after every scan (§10, 2026-09-02) — an unchanged pile must produce a byte-identical frame. If you find yourself caching "what changed since the last pile" to decide what to draw, stop: draw the pile.

**The reference implementations are the two Phase 2 consumers of the engine**: `crates/lastcall/src/commands/watch.rs` (the event loop shape — tokio runtime, `engine.run(timings)`, `select!` over `watcher.events`, bounded shutdown) and `crates/lastcall-engine/src/status.rs` (`row_line`, `render_human`: the text forms the nav rows reuse). For Ratatui test style, herdr's in-module `TestBackend` tests (`~/dev/git/herdr/src/ui/sidebar.rs`, `mod tests`) are the pattern for driving a widget without a terminal (they inspect `terminal.backend().buffer()` cells; you snapshot the `Display` form plus a style dump, deliverable 8) — read-only reference clone, never build or modify it.

## Deliverables

1. **CLI shape.** Bare `lastcall` (no subcommand) launches the TUI; `lastcall tui [--poll <secs>]` is the explicit spelling (`--poll` exactly as `watch`). `config`, `hello-herdr`, `status`, `watch` are unchanged. Launching with stdout not a TTY prints `lastcall: not a terminal; try \`lastcall status\`` and exits 2 — never draws into a pipe. Exit code 0 on `q`/Ctrl-C.
2. **Terminal lifecycle (`tui/term.rs`).** Raw mode, alternate screen, mouse capture, bracketed paste off; one `restore()` that is idempotent, uses only global crossterm commands on stdout (never the `Terminal` value, so it is callable from any thread's panic — a `blocking(..).expect(..)` re-panics on a runtime worker thread), and is called from the normal exit path, from a panic hook installed *before* raw mode (the original hook still runs, after restore, so the panic message lands on a sane terminal), and from Ctrl-C/SIGTERM. `tracing` never writes to stdout or stderr while the screen is up: the TUI installs a subscriber only when `LASTCALL_LOG_FILE` is set (append to that file, `EnvFilter` from `LASTCALL_LOG`), otherwise none.
3. **`tui/app.rs` — the `App` state (pure, no terminal, no engine handle, no I/O).** Owns: `roots: BTreeMap<PathBuf, RootView>` (sorted by path bytes; `RootView { meta: RootMeta, rows: Vec<Row>, groups: Vec<Group>, notices: Vec<String> }` where `RootMeta { path, name, kind, parent, badge, branch, head, in_progress, remote: Option<String> }` is built from a `RootState` by `RootMeta::of` — the only place the UI reads engine root metadata), `selection: Option<Selection>` with `enum Selection { Root(PathBuf), Row(PathBuf, Vec<u8>), Group(PathBuf, Annotation) }` (the nav cursor walks each listed root in the order `[Root, rows…, groups…]`), `focus: Nav | Diff`, `diff: DiffCursor { hunk: usize, scroll: usize }`, `nav_width: u16` (default 28, clamped 16..=60), `dragging: bool`, toggles `full_paths: bool`, `show_remote: bool` (default off), `help: bool`, `status: Option<StatusLine { text, at: Instant }>`, `now: Instant` (advanced by `Tick`; render computes ages from it, never from `Instant::now()`), `size: (u16, u16)` (set by `Resize`, used only for page sizes in `handle`; render always draws `frame.area()`), `refreshing: bool`. Entry points: `apply(&mut self, EngineEvent) -> Changed`, `handle(&mut self, Action) -> (Changed, Option<Effect>)` (`Effect::Refresh | SyncRoots | Quit`), and `sync_roots(&mut self, Vec<RootMeta>) -> Changed` (the seed step and every `RootsChanged` go through it). All are total functions with no I/O. `Changed` is the redraw signal — not `PartialEq` on `App`, and the hit map lives outside `App` (deliverable 6). Rules: a `Pile` for a root replaces that root's rows/groups/notices; **a root is listed iff its pile has rows** (§6.7 "appearing only when they have pending files or an attention flag"; the attention flag is herdr's, Phase 5); `[<op> in progress]` is a tag on a listed root, never a reason to list one; when the selected row or group disappears, select the next nav entry by path order in the same root, else that root's `Root` entry, else the next listed root's first entry, else nothing; a pile equal (`==`) to the one already held changes nothing — selection, cursor, scroll untouched and `Changed::No`; on any *changed* pile for the selected root, `hunk = min(hunk, hunks.len().saturating_sub(1))` and `scroll` is re-clamped; a root notice not previously held also sets the status line; `Head` → status line = its notice (else `HEAD a1b2c3d → d4e5f6a`), the root's `branch`/`head` update from the event, and the effect is `SyncRoots` (so `in_progress`, which the event does not carry, refreshes within one round trip); `RootsChanged` → removed roots drop (selection fallback), added roots get a `RootView` only when `SyncRoots` delivers their meta and are listed only after their first pile; `Notice` → status line; `Tick` advances `now` and is `Changed::Yes` only while `status` is `Some`. Hunk cursor: `HunkNext`/`HunkPrev` clamp at the ends (no wrap); `scroll` follows the cursor so the current hunk header is visible; selecting a different `Row` resets the cursor to hunk 0, re-selecting the same path (by key or by click) does not.
4. **`tui/render.rs` — frame = f(App, area).** Layout: header (1 line), body (nav | 1-col divider | main), status bar (1 line). Below 40×10 draw one line `terminal too small (40×10 minimum)` and nothing else; below 70 cols hide the nav and draw only the main view (focus forced to Diff; `Tab` still toggles once it fits again).
   - **Header:** `lastcall  <N> repos · <F> files · <H> hunks` (roots listed, rows, hunks summed) and on the right the watch scope (`watching <parent basename(s)>`). No Accept All (Phase 4), no herdr badge (Phase 5) — leave nothing where they will go; the header is one `Line` with two spans.
   - **Nav (§6.7 verbatim):** repos stacked with a horizontal-rule delimiter between them. Repo row: **bold** directory name; when `show_remote` and `remote` is `Some`, a dimmed `org/repo` after it (ellipsized to fit; hidden when no remote); worktree badge `[worktree of <basename>]` / nested badge `[nested in <basename>]`; in-progress tag `[merge in progress]` etc. Branch line beneath: `  <branch>` (or the short head when detached, `no commits`, or `draft`), then ` · <n> files`. File rows beneath: `  M name  +3 −1` — name-only by default, full relative path when `full_paths`; counts green/red and **live** (they are just the row's `added`/`deleted`); `Change` letter as `row_line`; collapsed rows marked `⊟` and rendered once (Phase 6 owns their semantics; here they are a single row like any other), flagged rows marked `⚑`, conflicted rows suffixed `[conflict]` (as `row_line`), `annotation` rendered as a dimmed `[upstream]`/`[mixed]` suffix; group rows after the file rows: `  upstream · 4 files` (C2), selectable, opening a main view that lists the group's paths. Selected row inverted; the focused pane's border highlighted. Root notices are not in the nav; they appear under the main-view header and, when new, on the status bar.
   - **Main view:** header line `<path>  <letter>  +a −d  [annotation]  (renamed from <old> 90%)`, then the root's pile notices dimmed one per line (invariant 2: why a row is pending is visible where it is opened; nothing when there are none), then the hunks: `@@ -a,b +c,d @@` header lines, context plain, inserts green, deletes red, the current hunk's header inverted; `Change::Mode` shows the synthetic hunk (`mode 100644 → 100755`); `Deleted` shows the all-deletion hunk; `Unreadable` and `Typechange` rows have no hunks and carry no reason field — the main view shows the pile notice whose prefix is `<path>: ` (e.g. `f2: cannot hash (directory); shown pending`), else `unreadable`; a collapsed row shows `collapsed (<glob|binary|size>) · +a −d · expands in a later phase` and no hunks; no selection shows `select a file (↑↓ or click) · ? for help`; the empty state (no roots listed) fills the main view with `nothing pending across <N> roots` and the root list with their branches. Only the visible window of lines is built (a 50 000-line diff must render in under 16 ms — `tests/test_perf_tui.rs`, `#[ignore]`, not a gate; the technique is to compute `(hunk, line)` offsets once per pile and slice).
   - **Status bar:** the current status line with its age (`committed on main (1 commit) · 3s`), else the key hints `↑↓ select  ⏎ open  n/p hunk  Tab focus  r refresh  ? help  q quit`. Ages are `now - at` from `App.now` (advanced by `Tick` once a second).
   - **Help overlay (`?`)**: the keymap table (deliverable 5), centered, any key closes.

5. **`tui/input.rs` — events → `Action`.** `Action` is the single vocabulary: `NavUp | NavDown | NavPageUp | NavPageDown | Open | FocusToggle | HunkNext | HunkPrev | ScrollUp(n) | ScrollDown(n) | ToggleFullPaths | ToggleRemote | Refresh | Help | Quit | Press(x, y) | Drag(x, y) | Release | Resize(w, h) | Tick`. Keymap: a `const` default table `DEFAULT_KEYMAP: &[(&str /*action name*/, &[&str] /*key specs*/)]` documented in `docs/dev/tui.md`, **overridable through a `[keys]` config table** (sponsor ruling 5, Amendment v1.3): each entry is `<action_name> = "<key>"` or `= ["<key>", …]` and *replaces* that action's defaults; key specs are `ctrl-x`/`alt-x`/`shift-x` modifiers plus a single character or a named key (`up down left right pageup pagedown home end enter esc tab backtab space backspace delete f1..f12`), case-insensitive, matched exactly (`shift-tab` and `backtab` are the same). The engine's `Config` gains `keys: BTreeMap<String, KeySpecs>` (untagged string-or-list, unknown top-level keys still a load error, §6.1) and nothing else — the engine never knows action names. The binary owns `input::Keymap::from_config(&config.keys) -> Result<Keymap, KeymapError>`: unknown action name, unparsable key spec, or the same key bound to two actions after merging is an error; `lastcall tui` reports it and exits 2 **before** raw mode, and `lastcall config` reports it too so a bad table is visible headlessly. Unit tests: the default table parses and has no duplicate binding, every `Action` has at least one default, each error class, an override replaces rather than appends, `ctrl-c` and `q` both quit by default. Defaults: `↑`/`k` `↓`/`j` `PageUp`/`PageDown`, `Enter`/`l` open (nav) / `h` back to nav, `Tab` focus toggle, `n`/`]` next hunk, `p`/`[` previous, `Space`/`b` page the diff, `f` full paths, `o` org/repo, `r` refresh, `?` help, `q` quit, `Esc` closes the help overlay else returns focus to the nav (it never quits), Ctrl-C quit (under raw mode it arrives as a key event, so map it in the table). Mouse: `Press` (button down — a click *is* the press) resolves through the `HitMap` the last render produced: `NavRoot` → `Selection::Root`, `NavRow` → `Selection::Row` plus focus Diff (so its key twin is `↓…` then `Enter`), `NavGroup` → `Selection::Group`, `DiffHunk(i)` sets the cursor, `DiffBody` focuses the diff, `Divider` sets `dragging`; `Drag(x, _)` while `dragging` resizes the nav (clamped); `Release` clears `dragging`; wheel scrolls whichever pane is under the pointer (nav: selection moves; diff: `ScrollUp/Down(3)`); a `Resize` invalidates the `HitMap`, so presses are ignored until the next render. **Every gate action — select repo, select file, hunk next/prev — is reachable by both a key and a mouse gesture, and both produce the same `App`** (deliverable 9 proves it).
6. **`tui/run.rs` — the loop.** `run(engine: Engine, timings: EngineTimings) -> Result<ExitCode>`: build the tokio runtime exactly as `watch.rs` does; `let watcher = engine.run(timings)`; **seed** with `app.sync_roots(blocking(&watcher.engine, |e| e.roots().iter().map(RootMeta::of).collect()).await)` — `Engine::open` performs no scan and `last_pile` is `None` until the watcher's first scans, so the first frame is the empty state with status `scanning <N> roots…` until piles arrive (as `watch` behaves). Terminal input: a dedicated `std::thread` looping `crossterm::event::poll(50 ms)` + `read()` under an `AtomicBool` stop flag, forwarding into a `tokio::sync::mpsc`; `read()` never returns on terminal restore (crossterm 0.29 blocks in `mio::Poll` on the tty fd), so the thread is never joined — the flag plus the 50 ms poll let it exit on its own. The loop is one `select!` over `watcher.events` (→ `apply`; `None` ⇒ the watcher died: status notice, then exit 0 the way `watch.rs` does), the input channel (→ `input::to_action` → `handle`), a local `mpsc<Local>` (`Local::Pile(root, pile) | Roots(Vec<RootMeta>) | RefreshDone`), a 1 s interval (→ `Tick`), `tokio::signal::ctrl_c()` (dead under raw mode where Ctrl-C is a key event; kept for `kill -INT`) and `signal(SignalKind::terminate())`. Render **at most once per iteration** and only when an `apply`/`handle`/`sync_roots` returned `Changed::Yes`; `render(&app, frame) -> HitMap` and the loop owns the `HitMap` (it is not in `App`). Effects: `Refresh` (ignored while `refreshing`) spawns a task that runs `blocking(scan_all)` and sends each pile into the local channel, so input and redraw keep flowing through a long scan; `SyncRoots` likewise spawns `blocking(roots → Vec<RootMeta>)`. The UI task never holds the engine mutex across an `.await` — every engine call goes through `blocking` (grep gate: `lock(` does not appear under `tui/`). `Quit` → `restore()` **first** (the screen is sane even if shutdown hangs), then `tokio::time::timeout(500 ms, watcher.join())`, then `runtime.shutdown_timeout(500 ms)`, exit 0.

## Traps (each is a verified failure elsewhere; design them out)

- **`std::sync::Mutex` held across `.await` deadlocks the watcher.** The watcher's scans lock the engine on `spawn_blocking`; a UI task that holds `lock()` while awaiting an event stalls every scan. Seed once synchronously, refresh through `blocking`, never hold a guard in `select!`.
- **A pile per scan, unchanged or not.** `watch` publishes after every scan (§10); the nav must not flicker, the diff must not scroll, and the redraw must be skipped (`Changed::No`) when the pile is equal to the one held.
- **`Display` snapshots carry no styles.** `TestBackend`'s text form is symbols only; inversion, colors and dimming are invisible to it — hence the style dump beside every frame (deliverable 8).
- **Temp-dir names are unique per run** (`<prefix>-<pid>-<nanos>-<n>`); any path, basename or local-origin URL that leaks into a frame or the golden breaks determinism. The parent is always `<TempDir>/W/`, local origins render as no remote.
- **Selection by index breaks under live updates.** A new untracked file sorting above the selected one moves every index; path keys do not move.
- **Raw mode outlives a panic.** Install the panic hook before `enable_raw_mode`; `restore()` must be safe to call twice and from the hook.
- **`tracing` to stderr under the alternate screen** corrupts the frame and every later snapshot of a PTY transcript. File or nothing.
- **Mouse capture leaks after exit** (`?1000h` left on): the sponsor's shell then prints escape junk on every click. The PTY test asserts the off sequences.
- **`TestBackend` frames include trailing spaces and box-drawing**; snapshot the `Display` form, never a hand-trimmed string, and keep the terminal size in the snapshot name when it is not 100×30.
- **Wide and combining characters** (`é`, CJK, emoji in file names) break column math if you truncate by `char`; use `unicode-width` and let `Line::width()` decide fit. `tui_nav_full_paths` must include one wide-char path (`docs/日本語.md` added to the fixture for that snapshot) so the column math is pinned.
- **Non-UTF-8 paths** are `Vec<u8>`; render lossy (`Row::path_lossy`) and key selection on the bytes.
- **`fixture_parent::build` performs first sight before the history operations**; opening a *second* engine on the same state dir sees the same ledger. Do not rebuild the fixture per snapshot — build once per test binary and open fresh engines.
- **Terminal size at first draw.** `TestBackend::new(w, h)` fixes it; the real terminal reports it through `crossterm::terminal::size()` and then `Resize` events. Render with `frame.area()`, never a cached size.
- **`crossterm::event::read()` never returns on terminal restore** (it blocks in `mio::Poll` on the tty fd; nothing in `disable_raw_mode`/`LeaveAlternateScreen` wakes it), and `EventStream` needs `futures-core` + a `StreamExt` that is not in the tree. The shape is the detached reader thread with `poll(50 ms)` + stop flag (deliverable 6), never joined.
- **`--poll 1` under the TUI means a full rescan every second**; on the fixture that is ~50 ms and fine, on the sponsor's real parent dir it is noticeable — the default stays 10 s / 30 s; `--poll` is the sick-host escape hatch, exactly as for `watch`.
- **libtest swallows passing tests' output**: the PTY timing and every skip go through `stderr().write_all` and are named in the report.
- **`git add -A` / `git add .` are denied**; stage explicitly. `git push` never. `z_ignore/`, `scripts/harness/work/` and other worktrees are not yours.
- **The reference clone `~/dev/git/herdr` is read-only** — read its tests, never `cargo build` it.
