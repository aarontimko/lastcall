# Phase 3 Kickoff Prompt (operational artifact, not design)

Phase 3 of the lastcall phased program. Phase 2 closed on 2026-09-02 (PR #2, merged `ba62907`): the review engine exists as a library — private store, seen-tree ledger, private-index scan, hunks, accept operations, git awareness, root discovery, draft roots, the watcher, crash safety — plus two headless surfaces, `lastcall status [--json]` (`status_version: 1`) and `lastcall watch`. Nothing has a screen yet. This phase puts the **read-only TUI** on top of exactly the types Phase 2 built: header, left nav (repos, branch lines, file rows with live counts), diff view with hunk navigation, watcher-driven live updates, mouse plus keyboard. **No accept, no restore, no flag, no editor** — those are Phases 4, 7 and 8. It closes Gate 3 (§8, Phase 3). Phase 4 adds the accept loop to this exact UI, so the state model and the widget boundaries are the product of this phase as much as the pixels are.

**The spine of this phase is invariant 9 (§2) applied to a screen: event streams are hints, engine piles are truth.** The TUI holds *no* review state of its own. Every row, count and hunk it draws comes from a `Pile` the engine published (`EngineEvent::Pile`) or returned from a scan the user asked for; the UI never diffs, never hashes, never reads a file, never spawns git (the single spawn site stays `git.rs`, gate grep). A screen is a pure function of `(App state, terminal size)`, and `App` is a pure function of the event sequence it was fed — which is what makes the whole UI testable through `ratatui::backend::TestBackend` with no terminal and drivable by the same `Action`s whether they came from a key or a mouse click. **Selection is by path, never by index**: a pile that arrives while the user is reading a hunk must not move what they are looking at (§6.7 "scroll position preserved best-effort"), and the engine may publish an unchanged pile after every scan (§10, 2026-09-02) — an unchanged pile must produce a byte-identical frame. If you find yourself caching "what changed since the last pile" to decide what to draw, stop: draw the pile.

**The reference implementations are the two Phase 2 consumers of the engine**: `crates/lastcall/src/commands/watch.rs` (the event loop shape — tokio runtime, `engine.run(timings)`, `select!` over `watcher.events`, bounded shutdown) and `crates/lastcall-engine/src/status.rs` (`row_line`, `render_human`: the text forms the nav rows reuse). For Ratatui test style, herdr's in-module `TestBackend` tests (`~/dev/git/herdr/src/ui/sidebar.rs`, `mod tests`) are the pattern — read-only reference clone, never build or modify it.

## Deliverables

1. **CLI shape.** Bare `lastcall` (no subcommand) launches the TUI; `lastcall tui [--poll <secs>]` is the explicit spelling (`--poll` exactly as `watch`). `config`, `hello-herdr`, `status`, `watch` are unchanged. Launching with stdout not a TTY prints `lastcall: not a terminal; try \`lastcall status\`` and exits 2 — never draws into a pipe. Exit code 0 on `q`/Ctrl-C.
2. **Terminal lifecycle (`tui/term.rs`).** Raw mode, alternate screen, mouse capture, bracketed paste off; one `restore()` that is idempotent and is called from the normal exit path, from a panic hook installed *before* raw mode (the original hook still runs, after restore, so the panic message lands on a sane terminal), and from Ctrl-C/SIGTERM. `tracing` never writes to stdout or stderr while the screen is up: the TUI installs a subscriber only when `LASTCALL_LOG_FILE` is set (append to that file, `EnvFilter` from `LASTCALL_LOG`), otherwise none.
3. **`tui/app.rs` — the `App` state (pure, no terminal, no engine handle).** Owns: `roots: BTreeMap<PathBuf, RootView>` (sorted by path bytes; `RootView { name, kind, badge, branch, head, in_progress, remote: Option<String>, rows: Vec<Row>, groups: Vec<Group>, notices }`), `selected: Option<(PathBuf /*root*/, Option<Vec<u8>> /*row path*/)>`, `focus: Nav | Diff`, `diff: DiffCursor { hunk: usize, scroll: usize }`, `nav_width: u16` (default 28, clamped 16..=60), toggles `full_paths: bool`, `show_remote: bool`, `help: bool`, `status: Option<StatusLine { text, at: Instant }>`, `size: (u16, u16)`, and the **hit map** the last render produced (`Vec<(Rect, Target)>` where `Target` is `NavRoot(path) | NavRow(root, path) | NavGroup(root, kind) | Divider | DiffHunk(index) | DiffBody`). Two entry points: `apply(&mut self, EngineEvent)` and `handle(&mut self, Action) -> Option<Effect>` (`Effect::Refresh | Quit`); both total functions with no I/O. Rules: a `Pile` for a root replaces that root's rows/groups/notices; **a root is listed only while its pile has rows or its `in_progress` is `Some`** (§6.7 "appearing only when they have pending files or an attention flag"; the herdr flag is Phase 5); when the selected row disappears, select the next row by path order in the same root, else that root's first row, else the next listed root, else nothing; when a pile is unchanged (`==` on `Pile`) nothing about selection, cursor or scroll moves; `Head` → status line = its notice (or `HEAD a1b2c3d → d4e5f6a` when there is none) and the root's `branch`/`head`/`in_progress` update; `RootsChanged` → removed roots drop (with selection fallback), added roots wait for their first pile; `Notice` → status line. Hunk cursor: `HunkNext`/`HunkPrev` clamp at the ends (no wrap); `scroll` follows the cursor so the current hunk header is visible; changing the selected row resets the cursor to hunk 0, re-selecting the same row (same path) does not.
4. **`tui/render.rs` — frame = f(App, area).** Layout: header (1 line), body (nav | 1-col divider | main), status bar (1 line). Below 40×10 draw one line `terminal too small (40×10 minimum)` and nothing else; below 70 cols hide the nav and draw only the main view (focus forced to Diff; `Tab` still toggles once it fits again).
   - **Header:** `lastcall  <N> repos · <F> files · <H> hunks` (roots listed, rows, hunks summed) and on the right the watch scope (`watching <parent basename(s)>`). No Accept All (Phase 4), no herdr badge (Phase 5) — leave nothing where they will go; the header is one `Line` with two spans.
   - **Nav (§6.7 verbatim):** repos stacked with a horizontal-rule delimiter between them. Repo row: **bold** directory name; when `show_remote` and `remote` is `Some`, a dimmed `org/repo` after it (ellipsized to fit; hidden when no remote); worktree badge `[worktree of <basename>]` / nested badge `[nested in <basename>]`; in-progress tag `[merge in progress]` etc. Branch line beneath: `  <branch>` (or the short head when detached, `no commits`, or `draft`), then ` · <n> files`. File rows beneath: `  M name  +3 −1` — name-only by default, full relative path when `full_paths`; counts green/red and **live** (they are just the row's `added`/`deleted`); `Change` letter as `row_line`; collapsed rows marked `⊟` and rendered once (Phase 6 owns their semantics; here they are a single row like any other), flagged rows marked `⚑`, conflicted rows marked `!`, `annotation` rendered as a dimmed `[upstream]`/`[mixed]` suffix; group rows after the file rows: `  upstream · 4 files` (C2), selectable, opening a main view that lists the group's paths. Selected row inverted; the focused pane's border highlighted. Root notices are not in the nav (status bar).
   - **Main view:** header line `<path>  <letter>  +a −d  [annotation]  (renamed from <old> 90%)`, then the hunks: `@@ -a,b +c,d @@` header lines, context plain, inserts green, deletes red, the current hunk's header inverted; `Change::Mode` shows the synthetic hunk (`mode 100644 → 100755`); `Deleted` shows the all-deletion hunk; `Unreadable` shows `unreadable: <reason from the row>`; a collapsed row shows `collapsed (<glob|binary|size>) · +a −d · expands in a later phase` and no hunks; no selection shows `select a file (↑↓ or click) · ? for help`; the empty state (no roots listed) fills the main view with `nothing pending across <N> roots` and the root list with their branches. Only the visible window of lines is built (a 50 000-line diff must render in under 16 ms — `tests/test_perf_tui.rs`, `#[ignore]`, not a gate; the technique is to compute `(hunk, line)` offsets once per pile and slice).
   - **Status bar:** the current status line with its age (`committed on main (1 commit) · 3s`), else the key hints `↑↓ select  ⏎ open  n/p hunk  Tab focus  r refresh  ? help  q quit`. Ages tick once a second.
   - **Help overlay (`?`)**: the keymap table (deliverable 5), centered, any key closes.
   - Every visual decision above is pinned by a snapshot (deliverable 8); if you must deviate, deviate in the snapshot and say why in the report.
5. **`tui/input.rs` — events → `Action`.** `Action` is the single vocabulary: `NavUp | NavDown | NavPageUp | NavPageDown | Open | FocusToggle | HunkNext | HunkPrev | ScrollUp(n) | ScrollDown(n) | ToggleFullPaths | ToggleRemote | Refresh | Help | Quit | Click(x, y) | Drag(x) | Resize(w, h) | Tick`. Keymap (a `const` table `DEFAULT_KEYMAP: &[(KeyCode, Modifiers, Action)]`, documented in `docs/dev/tui.md`; **no config key** — §6.1's key set is frozen and "config-stubbed" means the table is the seam, not a file): `↑`/`k` `↓`/`j` `PageUp`/`PageDown`, `Enter`/`l` open (nav) / `h` back to nav, `Tab` focus toggle, `n`/`]` next hunk, `p`/`[` previous, `Space`/`b` page the diff, `f` full paths, `o` org/repo, `r` refresh, `?` help, `q`/`Esc` quit (Esc closes help first), Ctrl-C quit. Mouse: left click resolves through the hit map (`NavRoot` selects the root's first row, `NavRow` selects and opens, `NavGroup` selects the group, `DiffHunk(i)` sets the cursor, `DiffBody` focuses the diff), wheel scrolls whichever pane is under the pointer (nav: selection moves; diff: `ScrollUp/Down(3)`), drag starting on the divider resizes the nav (`Drag(x)` while the button is held; clamped). **Every gate action — select repo, select file, hunk next/prev — is reachable by both a key and a mouse gesture, and both produce the same `App`** (deliverable 9 proves it).
6. **`tui/run.rs` — the loop.** `run(engine: Engine, timings: EngineTimings) -> Result<ExitCode>`: build the tokio runtime exactly as `watch.rs` does; `let watcher = engine.run(timings)`; seed `App` from `lock(&watcher.engine)` (`roots()` → `RootView`s with `last_pile` when present) *before* the first draw so the first frame is not empty on a healthy host; then `select!` over `watcher.events` (→ `app.apply`), `crossterm::event::EventStream` (→ `input::to_action` → `app.handle`), a 1 s interval (→ `Tick`), and Ctrl-C. ## Traps (each is a verified failure elsewhere; design them out)

- **`std::sync::Mutex` held across `.await` deadlocks the watcher.** The watcher's scans lock the engine on `spawn_blocking`; a UI task that holds `lock()` while awaiting an event stalls every scan. Seed once synchronously, refresh through `blocking`, never hold a guard in `select!`.
- **A pile per scan, unchanged or not.** `watch` publishes after every scan (§10); the nav must not flicker, the diff must not scroll, and the redraw must be skipped when the frame would be identical.
- **Selection by index breaks under live updates.** A new untracked file sorting above the selected one moves every index; path keys do not move.
- **Raw mode outlives a panic.** Install the panic hook before `enable_raw_mode`; `restore()` must be safe to call twice and from the hook.
- **`tracing` to stderr under the alternate screen** corrupts the frame and every later snapshot of a PTY transcript. File or nothing.
- **Mouse capture leaks after exit** (`?1000h` left on): the sponsor's shell then prints escape junk on every click. The PTY test asserts the off sequences.
- **`TestBackend` frames include trailing spaces and box-drawing**; snapshot the `Display` form, never a hand-trimmed string, and keep the terminal size in the snapshot name when it is not 100×30.
- **Wide and combining characters** (`é`, CJK, emoji in file names) break column math if you truncate by `char`; use `unicode-width` and let `Line::width()` decide fit. `tui_nav_full_paths` must include one wide-char path (`docs/日本語.md` added to the fixture for that snapshot) so the column math is pinned.
- **Non-UTF-8 paths** are `Vec<u8>`; render lossy (`Row::path_lossy`) and key selection on the bytes.
- **`fixture_parent::build` performs first sight before the history operations**; opening a *second* engine on the same state dir sees the same ledger. Do not rebuild the fixture per snapshot — build once per test binary and open fresh engines.
- **Terminal size at first draw.** `TestBackend::new(w, h)` fixes it; the real terminal reports it through `crossterm::terminal::size()` and then `Resize` events. Render with `frame.area()`, never a cached size.
- **Terminal input without a new dependency.** `crossterm::event::EventStream` needs the `event-stream` feature *and* a `StreamExt` to `.next()` it (`futures-util`, not in the tree). Use it only if `cargo tree -p lastcall -e normal | grep futures-util` already shows the crate; otherwise the zero-dependency shape is a dedicated `std::thread` looping `crossterm::event::read()` and forwarding into a `tokio::sync::mpsc` (the thread is detached; `read()` returns on the terminal restore). Either way the loop is one `select!`.
- **`--poll 1` under the TUI means a full rescan every second**; on the fixture that is ~50 ms and fine, on the sponsor's real parent dir it is noticeable — the default stays 10 s / 30 s; `--poll` is the sick-host escape hatch, exactly as for `watch`.
- **libtest swallows passing tests' output**: the PTY timing and every skip go through `stderr().write_all` and are named in the report.
- **`git add -A` / `git add .` are denied**; stage explicitly. `git push` never. `z_ignore/`, `scripts/harness/work/` and other worktrees are not yours.
- **The reference clone `~/dev/git/herdr` is read-only** — read its tests, never `cargo build` it.

## Operational rules

- **Sacred and untouchable:** the sponsor's real state dir (`~/.local/state/lastcall`), config (`~/.config/lastcall`, `~/.config/herdr`), every repo under `~/dev/git/` other than your worktree (the reference clones are read-only), and `z_ignore/`. ## Working agreements

- Grounded claims only: test names and counts, file paths, SHAs, pasted frames. "Looks right" is not evidence.
