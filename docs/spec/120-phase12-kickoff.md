## The model change, stated once

Today a draft root is "a directory and everything below it": first sight copies every file into the private store, every scan lists every file, and the glob that found it is re-walked four levels deep under every repository every thirty seconds. From this phase a draft root has a **scope**, decided by the entry that matched it, and everything that reads the root (first sight, the candidate set, the harness) reads the scope and nothing else. Two lines the design review drew and this file keeps: the rules decide what is **read**, never what is **listed** (listing costs nothing the rulings objected to, and a row is how a change stays visible); and every file in a tree that some root covers belongs to **exactly one root**, so nothing that was reviewed yesterday is reviewed by nobody today:

- **R1 Scope: plain is one folder, `/**` is the tree.** A `draft_dirs` entry without the `/**` suffix matches exactly as today (`z_ignore` still matches `repo1/z_ignore` under every parent dir and git root) but the root it makes is **non-recursive**: its scope is the regular files and symlinks directly inside the directory. Subdirectories are never entered by first sight or the listing and never hashed; a file in one is neither pending nor seen nor deleted *in this root* (it may belong to an enclosing root, below). The `/**` suffix, stripped and ignored today, now **opts into the recursive scope**: the tree below the directory, minus `.git` entries, nested repositories (D9, unchanged) and **what any draft root inside it reads**. An absolute entry follows the same rule (`/abs/notes` one folder, `/abs/notes/**` the tree). A directory matched by two entries, one plain and one `/**`, is one root with the recursive scope (the wider wins, whatever the entries' order: discovery merges the matches for one directory instead of keeping the first, `roots.rs:305`). **The exclusion rule (design review F2):** an enclosing root, git or `/**` draft, excludes from its own first sight and candidates exactly what an inner draft root *reads*: the inner directory's direct files when the inner root is plain, the whole directory when it is recursive. Today a git root excludes the whole directory of every draft root inside it (`excluded_dirs`, a prefix test); that stays right for a `/**` inner root and would be wrong for a plain one, where a file below the inner folder (`z_ignore/research/b.md` under a git root whose `z_ignore` is not ignored; `research/deep/c.md` under a `/**` root with a plain `z_ignore/research` inside) would be reviewed by nobody, when today the recursive root shows it. So `excluded_dirs` becomes a list of `(dir, recursive)` and `under_any` gains one check (for a plain inner root: the path has no further `/` after the prefix). The watcher's `classify_path` (`watcher.rs:311-314`, longest root prefix) still routes an event under the inner folder to the inner root even when the file belongs to the outer; the 30 s backstop marks every root due (`watcher.rs:776-781`), so that costs latency, never a hide; `engine.md` says so. The scope is a property of the discovered root (`DiscoveredRoot` gains it), re-evaluated at every discovery (open and each rescan) and carried onto an already-open root; a scope change is never a first sight (the ledger is kept; R6 trims it). **No config reload exists** (the only config seam, `set_search_depth`, is a session setting), so an edited entry takes effect at the next start, as every key does today; this phase adds no reload, and F7 is a restart scenario.
- **R2 Size: a draft root never reads a large file, and never hides one it has already recorded (design review F1).** Within the scope, a regular file whose `lstat` size is **at or above `collapse_size_bytes`** (the existing key, 512 KiB by default; `symlink_metadata`, never following a link; a symlink's own size is its link text and is always read) is **never read**: never hashed, never copied into the store, never in a tree written by first sight. The size decides what is *read*, not what is *listed*. (a) A large file with no entry in the seen tree and no override is not a row; the root gets **one notice per scan** with the count, `1 file over 512 KiB not read` (`with_thousands`; the threshold printed as the config value in KiB, or bytes when not a whole KiB; no notice when the count is 0; replacing the previous scan's notice, never accumulating; no root-name prefix, since a pile notice prints under the root's header, F10). (b) A large file that **is** in the record (a seen-tree entry written before this release, or written when the file was small and grown since; or an override) and is a candidate (the private index's `diff-files` says it changed, or its override names it) is a **row**: collapsed as the hunk ladder collapses, labelled `not read (over 512 KiB)`, with no current-side hash and no hunks. Accepting it writes `TreeWrite::Remove` for the path, after which it is a never-recorded large file and silent (counted, not shown); undoing that accept restores the entry and the row. A row is not counted. A recorded large file that has not changed is not a candidate, is not read by lastcall and is not counted (the private index's refresh compares stat data, as today). One that shrinks below the threshold is read again as a changed or new file. The predicate is one function, used by first sight (`tree_of_disk`) and the scan's candidate filter. **Cost (F3):** the scan `lstat`s a draft root's candidates only inside `Store::hash_paths`, after the row-cap partition; the size filter must sit **before** the cap (a large file must not take one of the 10,000 rows), so the scan gains one `symlink_metadata` per candidate before the cap for draft roots, its metadata handed down to `hash_paths` so it is not repeated: a root with 100,000 changed paths pays 100,000 `lstat`s per scan, tens of milliseconds warm, stated in `engine.md`. A `NotFound` candidate (a recorded path deleted on disk) is admitted as a deletion, never counted. Git roots are not affected: a tracked file of any size is still a change; but the hunk ladder's boundary becomes **at or above** too (F11: `scan.rs:674` collapses at `>` while `docs/config.md:61` has promised at-or-above since Phase 3; one character, a **Fixed** entry in the CHANGELOG, carved out of R7).
- **R3 Discovery: the glob walk goes as deep as the entry says, and no deeper.** `matching_dirs` walks, below each base, exactly as many levels as the entry's pattern has components (`z_ignore` one level; `z_ignore/research` two; `notes/*/drafts` three), and only an entry with a `**` **component** (as in `**/z_ignore`; the `/**` suffix is not one, it is R1's scope switch) walks to `MAX_SEARCH_DEPTH` as today. The matcher is built with `literal_separator(true)` (design review F9): today's globset default lets `*` cross `/`, so `notes/*` also matched `notes/a/b` and made it a root; from this phase one component is one level by construction, `*` never crosses `/`, a `**` component still matches any number of levels, and a bare `**` entry (globset: match everything) is a `validate` error. Literal entries (`z_ignore`, `_drafts`) are unaffected; a CHANGELOG **Changed** entry says so for the `*` forms. The 30 s backstop still runs discovery (a new `z_ignore` folder created in a repository appears within 30 s, as today), and with the walk bounded by the entry the sponsor's cost (four levels of a large tree under every repository, every tick) is gone without gating discovery on events: one `read_dir` per base per component level, `file_type()` from the dirent, one `canonicalize` per match. *Judgment call, recorded for the phase close:* the ruling's words were "honour `search_depth`"; at the default `search_depth = 1` that would make a two-component entry such as `z_ignore/research` unmatchable under a repository, which the same ruling's naming example relies on, so the walk depth follows the entry instead, and `search_depth` keeps its one meaning (the repository walk). An entry whose walk would exceed `MAX_SEARCH_DEPTH` (five or more components) is a `validate` error, not a silent no-match.
- **R4 Names: the entry as matched plus `draft_dir_parents` directory names.** New config key `draft_dir_parents` (integer, default `1`, `validate`: 0 to 4). A draft root's **name** is the matched directory's path relative to its **base**, prefixed with the last `draft_dir_parents` directory names of that base, joined with `/`. The base for the name is the **deepest** base (parent dir or discovered git root) that contains the directory, whichever base the glob happened to match under, so the name depends on neither the order of the entries nor the order of the bases (design review F4: `**/z_ignore` found under `W` at two levels and `z_ignore` found under the git root `W/repo1` both name the same directory `repo1/z_ignore`; today `or_insert` at `roots.rs:305` would keep whichever came first). For a glob the relative path is the matched one, not the pattern text (`_dr*` matched at `_drafts` names `_drafts`). With the default, `z_ignore` under `repo1` is `repo1/z_ignore`, `z_ignore/research` under `repo1` is `repo1/z_ignore/research`, `notes` directly under the parent dir `…/dev/git` is `git/notes` (no special case for the parent dir), and `0` is the relative path alone. An absolute entry names the directory by its last `1 + draft_dir_parents` components. Fewer components than asked (a root near `/`) uses what exists. The name is computed at discovery (`DiscoveredRoot.name`), carried on `RootState` (`name()` returns it), refreshed on an open root by each rescan (a repository appearing above a draft folder changes the deepest base), and is what the nav row, the selected-root header, the `status` text form and every notice that names a root use. A name wider than the nav column is head-ellipsized (`ellipsize_head`, F13) so the distinguishing tail survives. **Git roots keep their basename** (the circle-back above is untouched). Same-named draft roots under two bases (`repo1/z_ignore` and `repo2/z_ignore`) are now distinct on screen by construction; two that still collide (two parents both ending in `git`) are told apart by R5.
- **R5 The path line.** When a root's own row is selected in the nav (any kind: git, worktree, draft), the right pane's header gains a second line, dim, with the root's absolute path, the home directory collapsed to `~` (`~/dev/git/repo1/z_ignore`), truncated at the pane width by the existing truncation rule if it does not fit. The home is `Engine::env().home()`, **canonicalized once at `Engine::open`** with the raw value as the fallback (design review F8: the `Env` stores the home as given and nothing else in the program resolves `~`; root paths are canonical, and on macOS the temp dir `/var/folders/…` canonicalizes to `/private/var/…`, so a `strip_prefix` against the raw home would never match in a test). Nothing else in the pane moves; a selected **file** row's pane is unchanged. In the snapshot and PTY fixtures the scene's home must be an ancestor of `W` so frames read `~/W/notes` and never carry the variable-length temp path: the scene home becomes a **parameter** of `fixture_parent::build` (the snapshot and PTY scenes pass the temp dir, `W`'s parent; the golden test, which builds with the temp dir as `W` itself, keeps `state/home`, so its `HOME` never resolves to the OS temp dir), the golden and every existing frame are re-checked byte-identical after that fixture move (they show basenames and the parent's basename, which does not change), then the path line is added, and the snapshot suite asserts that no frame contains `/var/` or `/private/`.
- **R6 Upgrade: a record written under a wider scope is valid and is trimmed by path shape.** A draft ledger from `v0.3.0` or earlier, or one written before the entry changed, may hold paths outside the new scope. Such paths are **never candidates** whatever list names them (the scope filter is applied after all three candidate sources, before the row cap). The trim's predicate is **path shape only** (design review F5): a path with a `/` under a plain root, or a path inside what an inner draft root reads (R1's exclusion rule). **Never size:** a recorded large file is R2's unread row, reviewed once and removed by the user's accept, never dropped silently (and the engine holds no blob sizes anyway: `TreeEntries` is path to `(Mode, Oid)`). The trim runs at **any scan** whose in-memory seen tree holds such a path (an O(n) pass over the tree's keys, no syscall): the first scan after open, and any scan after discovery changed the scope; a no-op otherwise. It goes through a new `Ops::trim(out_of_scope, fault)` (F7) wrapping the private `fold` with a `Remove` write per path, so it has compaction's properties: no undo entry, `seen_at` untouched, lock, merge, tmp + rename; blob overrides are folded into the tree first (as compaction does) and leave with their paths; **flag-only overrides on dropped paths are kept** (they are the user's notes, never candidates after the filter, and return with the path if the scope widens); the count comes from the merged ledger under the lock (a second process may already have dropped some; the removes themselves are idempotent); gated on `RootKind::Draft`; an early return when `seen_tree` is `None` and no out-of-scope override carries a blob, so a `pending` root's `null` never becomes an empty-tree oid. One notice, `2 paths outside the root's scope dropped from its record` (`with_thousands`, no prefix), and the private index (`Index::ensure`, seeded from the seen tree) stops carrying, refreshing and `lstat`-ing them on every scan. If the user widens the scope again (`/**`), those files come back as new (over-show, F7); nothing is hidden by the trim because nothing in it can be a row. **The trim is what bounds the plain listing**: `ls-files --others --directory` descends into any directory that still has index entries beneath it (the review's probes P4 and P12), so "keep the paths and report it" is a cost regression, not a neutral fallback; build the trim.
- **R7 Nothing else moves.** Root discovery of git roots, worktrees, nested repositories, `search_depth`, badges, the parent-dir layout of the state directory (nested draft roots file under the same parent dir as today: `file_under(&parents, path)` and `RepoPaths::under` key by the canonical path), the ledger schema (1.2), `status --json` (no new field: `root` already carries the full path; the golden changes only if a fixture path does), the herdr integration, the row cap, exports. Two carve-outs, both named above: the hunk ladder's boundary becomes at-or-above (R2, F11) and `*` in a `draft_dirs` glob no longer crosses `/` (R3, F9). `draft_initial` keeps both meanings over the new scope.

- **F4 — A plain entry reads one folder.** Setup: parent `W`, repo `W/repo1` with `.gitignore` `z_ignore/`, `W/repo1/z_ignore/a.md`, `W/repo1/z_ignore/research/b.md`, `W/repo1/z_ignore/research/deep/c.md`; `draft_dirs = ["z_ignore"]`. Action: edit `research/b.md` and `a.md` → pile `[a.md]`; add `research/deep/d.md` → pile unchanged; delete `research/b.md` → pile unchanged; accept `a.md` → `[]`; restart → `[]`. `status --json` lists no path under `research/`. Variant: `z_ignore/` **not** in `.gitignore` → `research/b.md` and `research/deep/c.md` are untracked candidates of the git root `repo1` and `a.md` is not (it is the draft root's); the edit to `research/b.md` shows under `repo1`, never under both roots, never under neither. *(H, I)*
- **F5 — `/**` opts into the tree.** Same setup with `draft_dirs = ["z_ignore/**"]`. Expect: first sight records `a.md`, `research/b.md`, `research/deep/c.md`; the edits of F4 give `[a.md, research/b.md]`, the add gives `research/deep/d.md`, the delete gives `research/b.md` as a deletion. *(H, I)*
- **F6 — A large file is never read, and a recorded one is never hidden.** Setup as F4 plus `z_ignore/big.bin` of exactly `collapse_size_bytes` bytes and `z_ignore/small.bin` one byte below it; `draft_dirs = ["z_ignore"]`. Expect: first sight records `a.md` and `small.bin`, not `big.bin`; the store holds no blob of `big.bin`'s content (`git -C <store> cat-file -e <oid of big.bin>` fails); the root carries the notice `1 file over 512 KiB not read`. Action: append one byte to `small.bin` (now at the threshold) → pile `[small.bin]`, a collapsed row labelled `not read (over 512 KiB)` with no current-side hash, the store still without its new content, notice still `1 file …` (a row is not counted); accept `small.bin` → pile `[]`, the seen tree no longer holds `small.bin`, notice `2 files …`; undo → the row is back, notice `1 file …`; accept again. Truncate `big.bin` to 10 bytes → pile `[big.bin]` (new, read), notice `1 file …`; add a second large file → notice `2 files …`, one notice, not two. Variant: the same with `draft_dirs = ["z_ignore/**"]` and `research/huge.bin` at the threshold → not read, counted. Upgrade form: a seen tree that already holds `big.bin`'s blob (the record of an earlier release) with `big.bin` unchanged on disk → no row, not counted, not read by lastcall; edit `big.bin` → pile `[big.bin]` unread; accept → `[]`, then counted. *(H, I)*
- **F7 — Scope change across a restart trims by path shape.** Setup as F5 (recursive, first sight recorded the tree), plus a flag on `research/b.md`. Action: config becomes `["z_ignore"]`; restart (no config reload exists; a config edit takes effect at the next start). Expect: the root keeps its ledger (no first sight, `seen_at` unchanged); at the first scan the record is trimmed to `a.md` with the notice `2 paths outside the root's scope dropped from its record` and no undo entry; pile `[]`; the flag survives in the ledger (not a row). Then config becomes `["z_ignore/**"]` again; restart → `research/b.md` and `research/deep/c.md` are pending as new (over-show, never hidden), `research/b.md` still flagged. A large file in the old record is never trimmed (F6's upgrade form). *(I)* Harness form: the trim only (`lc_scope_trim`), asserting the seen tree's paths before and after.
- **F8 — Nested draft roots: every file belongs to exactly one root.** Setup as F4 with `draft_dirs = ["z_ignore/**", "z_ignore/research"]`. Expect: two roots, `repo1/z_ignore` (recursive) and `repo1/z_ignore/research` (plain); `research/b.md` belongs to the inner root only (the outer root's first sight and candidates exclude `research/`'s direct files); `research/deep/c.md` belongs to the **outer** root (the inner root is plain and reads nothing below its folder, so the outer's exclusion stops at the inner's direct files); `a.md` belongs to the outer. An edit to `research/b.md` shows in `repo1/z_ignore/research` and not in `repo1/z_ignore`; an edit to `research/deep/c.md` shows in `repo1/z_ignore` and not in the inner root; neither is ever under both, or under neither. With `["z_ignore/**", "z_ignore/research/**"]` the inner root reads its tree and `research/deep/c.md` is the inner's. *(I)*
- **F9 — Names and the walk.** Setup: parent `W` = `<tmp>/W`; repos `W/repo1`, `W/repo2`, each with `z_ignore/` and `z_ignore/research/`; `W/notes/` directly under the parent; `draft_dirs = ["z_ignore", "z_ignore/research", "notes"]`. Expect with `draft_dir_parents` unset: roots named `repo1/z_ignore`, `repo1/z_ignore/research`, `repo2/z_ignore`, `repo2/z_ignore/research`, `W/notes`; with `draft_dir_parents = 0`: `z_ignore`, `z_ignore/research` (twice each; the path line tells them apart), `notes`; with `2`: `W/repo1/z_ignore`, …, `<tmp basename>/W/notes`. Order: `["z_ignore", "**/z_ignore"]` and `["**/z_ignore", "z_ignore"]` both name `repo1/z_ignore`, one root each. The walk: with `draft_dirs = ["z_ignore"]` and a directory `W/repo1/deep/deeper/z_ignore`, no root is discovered there (one level); with `["**/z_ignore"]` it is; `notes/*` matches `W/notes/a` and not `W/notes/a/b`. `draft_dir_parents = 5`, a five-component entry and a bare `**` entry are `validate` errors with the key named. *(unit)*

### 2. Engine

- `DiscoveredRoot { scope: DraftScope, name: String }`; `DraftScope { recursive: bool, max_bytes: u64 }` (git roots: `None`, or a `RootKind`-gated field); `roots::discover` computes both (R1, R3, R4), merging the matches for one directory (wider scope wins; the name from the deepest containing base); `matching_dirs(base, glob, depth)` with the glob built `literal_separator(true)`; a root's `excluded_dirs` is `Vec<(Vec<u8>, bool)>` (path, recursive) for git roots **and** `/**` draft roots, from the draft roots inside them and what each reads; `under_any` takes the flag.
- One predicate, `scope.admits(rel_path, symlink_metadata)`, used by `tree_of_disk` (through `walk_files` taking the scope and the excluded inner roots) and by the scan's candidate filter, which for a draft root runs one `symlink_metadata` per candidate **before** the row cap and hands the metadata to `hash_paths` (R2, F3); a candidate at or above the threshold is a row when the seen tree or an override holds it (collapsed, `not read (over 512 KiB)`, no current hash; accept writes `Remove`) and is counted otherwise; the count comes back from the scan for the notice. The listing for a plain root must not walk the tree: `ls-files --others --directory` **without** `--no-empty-directory` (git then prints a directory with no index entries beneath it without opening it, and prints it even when empty or unreadable), with the `.git` check done in `Index::others` before a `dir/` record is classified (`symlink_metadata(dir/.git)` per record: with a `.git` inside it is `Other::NestedRepo` as today, without one it is a plain subdirectory to ignore, never reported as a nested repository and never `rev-parse`d by `rescan`); prove with a probe on a fixture that the listing of a plain root with 10,000 files below one subdirectory does not read them, over a **trimmed** record and over a fresh one (spawn count or timing is fine; a unit test on the args and on the `.git` check is the minimum). The `/**` scope keeps the existing walk.
- The trim (R6) through a new `Ops::trim(out_of_scope, fault)` wrapping `fold` (no undo entry, `seen_at` unchanged, flag-only overrides kept, count under the lock, the `seen_tree = None` early return), gated on `RootKind::Draft`, run from the scan whenever the in-memory tree holds a path the shape predicate rejects, with its notice.
- `RootState.name` and the scope from discovery; `Engine::rescan` carries a changed name or scope onto an already-open root (R1, R4), without a first sight.
- The hunk ladder's boundary at `scan.rs:674` becomes `>=` (R2, F11), with its unit test at the boundary.
- Unit tests in `roots.rs` (scope from the entry, the wider-wins rule, names for every example in R4 including `0`, both entry orders of F9, the walk depth per entry, the `**` component, `notes/*` not matching `notes/a/b`), `store.rs` (`tree_of_disk` under each scope; the size predicate at the boundary: `== max_bytes` is out, `max_bytes - 1` is in; a symlink to a large file is in), `index.rs` (the `.git` check under `--directory`), `scan.rs` (the filter before the cap, the unread row for a recorded large file and its count exclusion, the notice text and its replacement, the count, `under_any` with the plain flag, the ladder at the boundary), `config/mod.rs` (`draft_dir_parents` default, bounds, the five-component entry, the bare `**`), `ops.rs` (the trim: seen tree paths before and after, no undo entry, `seen_at` unchanged, a blob override on a dropped path folded then gone, a flag override kept, the `None` early return).
