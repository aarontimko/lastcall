## The model change, stated once

Today a draft root is "a directory and everything below it": first sight copies every file into the private store, every scan lists every file, and the glob that found it is re-walked four levels deep under every repository every thirty seconds. From this phase a draft root has a **scope**, decided by the entry that matched it, and everything that reads the root (first sight, the candidate set, the harness) reads the scope and nothing else:

- **R1 Scope: plain is one folder, `/**` is the tree.** A `draft_dirs` entry without the `/**` suffix matches exactly as today (`z_ignore` still matches `repo1/z_ignore` under every parent dir and git root) but the root it makes is **non-recursive**: its scope is the regular files and symlinks directly inside the directory. Subdirectories are never entered, never listed, never hashed; a file in one is neither pending nor seen nor deleted. The `/**` suffix, stripped and ignored today, now **opts into the recursive scope**: the tree below the directory, minus `.git` entries, nested repositories (D9, unchanged) and **any other draft root inside it** (the same exclusion a git root applies to its owned draft dirs today, `engine.rs:791`; today it is empty for drafts). An absolute entry follows the same rule (`/abs/notes` one folder, `/abs/notes/**` the tree). A directory matched by two entries, one plain and one `/**`, is one root with the recursive scope (the wider one wins, deterministically, whatever the entries' order). The scope is a property of the discovered root (`DiscoveredRoot` gains it) and is re-evaluated at every discovery, so editing the entry and pressing `r` changes it without a restart; a scope change is not a first sight (the ledger is kept).
- **R2 Size: a draft root never reads a large file.** Within the scope, a regular file whose `lstat` size is **at or above `collapse_size_bytes`** (the existing key, 512 KiB by default; `symlink_metadata`, never following a link; a symlink's own size is its link text and is always in scope) is **outside the scope**: never hashed, never copied into the store, never a row, never in the seen tree. First sight (`tree_of_disk`) and the candidate filter apply the same predicate; the D6 `symlink_metadata` call the scan already makes is where the size is read, so the check costs no extra syscall on the scan path. The root gets **one notice per scan** naming the count, `z_ignore: 225 files over 512 KiB not read` (`with_thousands`; the threshold printed as the config value in KiB, or bytes when not a whole KiB; no notice when the count is 0), replacing the previous scan's notice, never accumulating. A file that grows across the threshold leaves the scope (its row disappears; the seen tree keeps the old blob until an accept-all or compaction folds the record, which is over-show-safe: nothing the user has not seen is hidden, the file is simply no longer reviewed); one that shrinks below it enters the scope as a new or changed file. Git roots are **not** affected: a tracked file of any size is still a change (the hunk ladder collapses it, as today).
- **R3 Discovery: the glob walk goes as deep as the entry says, and no deeper.** `matching_dirs` walks, below each base, exactly as many levels as the entry's pattern has components (`z_ignore` one level; `z_ignore/research` two; `notes/*/drafts` three), and only an entry with a `**` **component** (as in `**/z_ignore`; the `/**` suffix is not one, it is R1's scope switch) walks to `MAX_SEARCH_DEPTH` as today. The 30 s backstop still runs discovery (a new `z_ignore` folder created in a repository appears within 30 s, as today), and with the walk bounded by the entry the sponsor's cost (four levels of a large tree under every repository, every tick) is gone without gating discovery on events. *Judgment call, recorded for the phase close:* the ruling's words were "honour `search_depth`"; at the default `search_depth = 1` that would make a two-component entry such as `z_ignore/research` unmatchable under a repository, which the same ruling's naming example relies on, so the walk depth follows the entry instead, and `search_depth` keeps its one meaning (the repository walk). An entry whose walk would exceed `MAX_SEARCH_DEPTH` (five or more components) is a `validate` error, not a silent no-match.
- **R4 Names: the entry as matched plus `draft_dir_parents` directory names.** New config key `draft_dir_parents` (integer, default `1`, `validate`: 0 to 4). A draft root's **name** is the matched directory's path relative to the base it matched under (`z_ignore`, `z_ignore/research`; for a glob the matched relative path, not the pattern text, so `_dr*` matched at `_drafts` names `_drafts`), prefixed with the last `draft_dir_parents` directory names of the base, joined with `/`: with the default, `z_ignore` matched under `repo1` is `repo1/z_ignore`, `z_ignore/research` under `repo1` is `repo1/z_ignore/research`, `notes` directly under the parent dir `…/dev/git` is `git/notes` (no special case for the parent dir), and `0` is the matched relative path alone. An absolute entry names the directory by its last `1 + draft_dir_parents` components. Fewer components than asked (a root near `/`) uses what exists. The name is computed at discovery (`DiscoveredRoot.name`), carried on `RootState` (`name()` returns it), and is what the nav row, the selected-root header, the `status` text form and every notice that names a root use. **Git roots keep their basename** (the circle-back above is untouched). Same-named draft roots under two bases (`repo1/z_ignore` and `repo2/z_ignore`) are now distinct on screen by construction; two that still collide (two parents both ending in `git`) are told apart by R5.
- **R5 The path line.** When a root's own row is selected in the nav (any kind: git, worktree, draft), the right pane's header gains a second line, dim, with the root's absolute path, the home directory collapsed to `~` (`~/dev/git/repo1/z_ignore`; the home is the engine `Env`'s, the same one config `~` resolution uses), truncated at the pane width by the existing truncation rule if it does not fit. Nothing else in the pane moves; a selected **file** row's pane is unchanged. In the snapshot and PTY fixtures the scene's home must be an ancestor of `W` so frames read `~/W/notes` and never carry the variable-length temp path: make the scene's home the temp dir itself (or a `home/` that `W` sits under), re-check that the golden and every existing frame are byte-identical after that fixture move (they show basenames and the parent's basename, which does not change), then add the path line.
- **R6 Upgrade: a record written under the old scope is valid and is trimmed once.** A draft ledger from `v0.3.0` or earlier may hold paths outside the new scope (subdirectory paths under a now-plain root; files at or above the threshold). Such paths are **never candidates** whatever list names them (the scope filter is applied after all three candidate sources, before the row cap). At the first scan after open, when the seen tree holds out-of-scope paths, the engine folds them out in one `write_tree(Some(seen), Remove…)` through `Ops` (the `commit` path: lock, merge, tmp + rename; an undo entry is **not** written, the record's `seen_at` does not move) and pushes one notice, `z_ignore: 12,000 paths outside the root's scope dropped from its record`, so the private index (`Index::ensure`, seeded from the seen tree) stops carrying, refreshing and `lstat`-ing them on every scan. Overrides on out-of-scope paths are dropped in the same fold. If the user widens the scope again (`/**`), those files come back as new (over-show, F7); nothing is hidden by the trim because nothing in it can be a row. When the primitives do not fit this in a small change, keep the paths and report it: the filter alone is correct, the trim is the cost fix.
- **R7 Nothing else moves.** Root discovery of git roots, worktrees, nested repositories, `search_depth`, badges, the parent-dir layout of the state directory, the ledger schema (1.2), `status --json` (no new field: `root` already carries the full path; the golden changes only if a fixture path does), the herdr integration, the row cap, the hunk ladder, exports. `draft_initial` keeps both meanings over the new scope.
