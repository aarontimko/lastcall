# Phase 1 Kickoff Prompt (operational artifact, not design)

Phase 1 of the lastcall phased program. Phase 0 closed on 2026-09-01: the design corpus [`00-spec.md`](00-spec.md) is stamped, §5 (herdr surface) and §6 (our contracts) are frozen at v1.0, and every G0 question is ruled in §10. Nothing has been built. This phase lays the substrate every later phase stands on: the crate layout and toolchain, the `just` targets and CI that every gate cites, the config layer every phase reads, the herdr client state machine with the mock server that makes it unit-testable, and a `hello-herdr` command the sponsor can run inside a real herdr session. It closes Gate 1 (§8, Phase 1).

**The spine of this phase is invariant 9 (§2): events are hints, snapshots are truth.** Every push-channel input (herdr events now; filesystem events in Phase 2) only ever *schedules* a resync against an authoritative source (`session.snapshot`, `pane.get`, `pane.list`). No state the user relies on is ever derived solely from having observed an event. This is load-bearing because herdr's delivery is verifiably lossy (§5.6: one event per subscription per 100 ms tick, a 512-entry ring with no gap indicator, a 5 s slow-consumer kill). Build the client so that a test can drop any event, reorder any burst, or sever the connection, and the client's cached state still converges to the snapshot. A client that "applies" a `pane_updated` event to its cache as truth is wrong even when it looks right in the happy path.

Two verified herdr facts shape the client's topology and must not be "simplified" away: (1) agent status transitions are **invisible to global subscriptions** (`emit_pane_state_update` in herdr's `src/app/api.rs:612-661` emits `pane_updated` only on an agent-name change), so each agent-bearing pane gets its own `pane.agent_status_changed` subscription (§5.4); (2) the `done → idle` flip emits **no global event at all** (§5.7), so `*_focused` events and a 30 s fallback timer drive resyncs (§5.6). A worker who finds these inconvenient should re-read §5.4's **[corrected]** paragraph rather than redesign.

5. **herdr client** (`lastcall_engine::herdr`), in these modules:
   - `wire`: every request, response, event, and payload type we consume (§5.5 table, §5.8 shapes, `ping`/`session.snapshot`/`pane.get`/`pane.list`/`worktree.list`/`events.subscribe` params and results; `notification.show` and `agent.focus` types may be defined now but are unused until Phase 5). Serde with **no** `deny_unknown_fields`; every optional field is `Option`; unknown `event` strings and unknown `AgentStatus` values deserialize to an `Unknown(String)` variant rather than failing. Error responses are detected by presence of `error` vs `result`; codes are plain strings matched by name (§5.1); `not_found` is never matched as a code.
   - `transport`: tokio `UnixStream` newline-JSON. `request(socket, method, params) -> Result<Value>` (one connection, one line out, one line in, close; `params` always present, `{}` for `ping`); `subscribe(socket, subscriptions) -> Result<EventStream>` (writes the request, awaits the `subscription_started` ack line, then yields event lines; an error line instead of the ack is returned as `SubscribeError` and the caller must treat the connection as closed). Request lines over 1 MiB are refused client-side. Timeouts on every await.
   - `discovery`: §6.6 session discovery. `HERDR_SOCKET_PATH` authoritative when set; else `<config_dir>/herdr.sock` (config_dir = `$XDG_CONFIG_HOME/herdr` or `~/.config/herdr`); else enumerate `<config_dir>/sessions/*/herdr.sock` and keep the ones that answer `ping`; `herdr.session` pins one; multiple live and no pin → `Discovery::Ambiguous(names)` and the caller shows the notice. All paths come from an injected `Env`, never `std::env` directly, so tests can never touch the real socket.
   - `guard`: `ping` → `Compat::{Ok{version, protocol}, Mismatch{server_protocol}, Absent}`. We require protocol `21` exactly in v1 (a constant `SUPPORTED_PROTOCOL: u32 = 21`); mismatch degrades to standalone with a notice string, never a panic.
   - `client`: the state machine, written against a `Transport` trait so the mock server (deliverable 6) and the real socket are interchangeable. Owns: the lifecycle subscription connection (§5.4 set, verbatim), one status connection per agent-bearing pane, the cache (`workspaces`, `panes`, `agents` from the snapshot, keyed by ids, never by `number`), the resync scheduler, the reconnect loop. Behavior, each a testable rule:
     1. Bootstrap = subscribe → ack → `session.snapshot` on a second connection → install snapshot → if any event was buffered during setup, schedule one resync → stream. Buffered events are never applied as state (§5.3 step 3).
     2. Events schedule work; they do not mutate cached truth. `pane_created`/`pane_agent_detected` → open a status subscription for that pane (if it has an agent) and schedule a resync; `pane_closed`/`pane_exited` → close its status subscription; any `*_focused` → resync (single pane: `pane.get` for that pane; otherwise snapshot); everything else → schedule resync. (Installing the whole `PaneInfo` carried by `pane_created`/`pane_updated` into the cache **as a provisional entry pending resync** is permitted, because the resync overwrites it; the test in rule 6 pins this.)
     3. Status connection construction failing with `pane_not_found` = pane gone, no retry; transport failure = reconnect path.
     4. Every resync reconciles open status connections against `snapshot.panes`, tearing down any whose pane is absent (§6.6, F9).
     5. Resync coalescing: at most one `session.snapshot` per 500 ms (trailing edge); the 30 s fallback timer; reconnect (with capped exponential backoff) re-runs the full bootstrap.
     6. Status changes are emitted to the engine as `AgentStatusChanged { pane_id, workspace_id, from, to, agent }` **deduplicated against last-known state**, and the status of record is whatever the latest snapshot or `pane.get` said, with per-pane events applied only when they are newer than the last resync's view of that pane (define "newer" as: received after the last completed resync; a resync always wins a tie).
     7. Output to the rest of the program is a `tokio::sync::mpsc` of `HerdrEvent` (`Connected{version,protocol}`, `Disconnected{reason}`, `Standalone{notice}`, `AgentStatusChanged{..}`, `PaneAssociation{pane_id, cwd, foreground_cwd}` on every resync, `WorktreeChanged{..}` from worktree events) plus a `Snapshot` accessor. Nothing in the engine depends on the client (§6.6 first sentence) — the module must compile out cleanly behind a feature flag or be unreferenced by anything but the binary.
   `notification.show`, `report_metadata`, and `agent.prompt` are **not** implemented in this phase.

## Traps (each has bitten someone; design them out)

- **Your own shell may be inside herdr.** If `HERDR_SOCKET_PATH`/`HERDR_ENV` are set in your environment, a test that reads `std::env` would connect to the sponsor's live session. Every path and env read goes through the injected `Env`; unit tests construct it explicitly; the integration spawner clears `HERDR_*` from the child env.
- **`params` is required on every method**, including `ping` (`{}`), or herdr answers `invalid_params`.
- **Two event envelope shapes** (§5.5): lifecycle events are snake_case with a tagged `data.type`; the three per-pane events are dotted with untagged data. Parse `event` as an opaque string and branch on both; do not `#[serde(tag)]` across the union.
- **No `id` on pushed events.** Never correlate them to the subscribe request.
- **Subscription failure closes the connection** — there are no partial subscriptions. The stream type must surface "closed after error" distinctly from "closed by peer later".
- **`revision` is not a change detector** (§5.8). Do not use it for dedupe.
- **`number` renumbers.** Key on `workspace_id`.
- **Herdr's debug builds use `herdr-dev`** as the app dir (§5.1). Irrelevant to the release binary you fetch, relevant if you ever build herdr locally — don't.
- **`deny_unknown_fields`**: forbidden on herdr-facing types, required on config types. The gate greps for both.
- **Rust 1.68.** If `cargo --version` inside the worktree does not print 1.98.0, the toolchain pin is not being honored; STOP and report rather than "fixing" the pin downward — ratatui 0.30.2 needs ≥1.88.
- **Downloads**: only `just herdr-fetch` of the pinned official release asset. Nothing else is fetched from the network in this phase.
- **`git add -A` / `git add .` are denied** by the committed allowlist; stage files explicitly. The worktree directory (`.claude/worktrees/`) and `scripts/harness/work/` are gitignored; `z_ignore/` is gitignored and not yours.
