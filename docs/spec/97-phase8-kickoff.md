A live symlink or a deletion row (`rendered.oid == None`) → new `Refused::NotEditable { path, why }` (`Display`: `<path>: not a regular file; not saved`).
   - *Oid first, then write (F1):* `oid = store.hash_bytes_as(rel, &bytes)?` **before any write** (a hashing error is `OpsError`, nothing touched); then `restore::write_bytes(store, rel, &bytes, Some(live.mode), before_rename)` — the buffer's bytes verbatim (the TUI read the worktree bytes, CRLF and all, so what goes back is what the user saw), the live mode; `before_rename` holds only the second CAS (`second_cas`). No fresh read or hash after the rename, ever: the oid the override gets is the oid of the bytes that were written, so an agent's write in the rename-to-ledger window shows as pending at the rescan instead of being blessed.
   - *Ledger, after the file:* `set_override(key, Some(oid), Some(live.mode))` + `commit(fault)`. Faults (F10): `KillAt(AfterLedgerTmpWrite)` leaves the new bytes on disk and the old ledger — the edit is **pending** at the rescan, nothing is lost (`ops_save_file_that_dies_before_the_ledger_shows_the_edit_pending`); `fails_at(AfterTempWrite)` leaves nothing written and no temp file (`ops_save_file_that_fails_before_the_rename_leaves_no_trace`). No new fault point. The doc comment beside `accept_hunk`'s A3 note says why the save has the live CAS and accept-hunk has not.
   - *Errors that are not refusals (F17):* `EACCES` on the temp file or the rename, `ENOSPC`, a vanished parent → `OpsError` (from `WriteError`); the TUI keeps the editor and its buffer open and names the error (deliverable 8).

2. **The editor command (binary, pure; gate item 2).** `tui/editor.rs`: `EditorCommand::resolve(var: &dyn Fn(&str) -> Option<String>) -> Result<EditorCommand, EditorError>` — `$VISUAL` if set and non-blank, else `$EDITOR`, else `vi`; split on ASCII whitespace, **no shell** (a value with quotes or `$` is used as split; documented). `argv(&self, file: &Path, line: usize) -> Vec<OsString>`: by the program's basename — `vi vim nvim view nano micro emacs emacsclient` → `+<line> <file>`; `hx` → `<file>:<line>`; `code codium` → `--goto <file>:<line> --wait`; `subl` → `<file>:<line> --wait`; `zed` → `<file>:<line> --wait`; `kak` → `+<line> <file>`; anything else → `<file>` alone (no line; the status says `opened in <basename> (no line flag known)`). A **non-waiting** editor (`code` without `--wait` when resolution misses the table, `emacsclient -n`, a GUI app launched through `open`) returns before its save: the file is unchanged on return, the status says `no change`, and the later save shows as pending like any other edit — documented as the expected shape in `tui.md` (F3). Unit tests per row and for the fallback order; `EditorError::Unset` never happens (there is always `vi`), `EditorError::Blank` when the variable is set to whitespace.
3. **Post-editor blessing (engine seam reuse; ruling P1 = Amendment v1.8, sponsor-ratified).** No new engine op. After the editor exits the TUI rehashes the path off the UI task (new `Engine::current(root, path) -> Result<Current, EngineError>`, a `hash_path` behind the engine lock; `Effect::EditorReturned { root, rendered }` → `Local::EditorReturned { root, rendered, live: Current }`) and, when `live` is a **regular file** whose `(oid, mode)` differs from `rendered`, opens the confirm **`<path> changed while your editor was open — mark as reviewed?`** (`Enter` / `y` yes, `Esc` / `n` no; the sponsor's addition to P1, 2026-09-06): yes issues `AcceptRequest::File(Rendered { oid: live.oid, mode: live.mode, ..rendered })` — the override becomes the content the editor left behind, status `reviewed <path>`; no writes nothing, status `<path> left pending`, and the row shows the delta like any agent change. The confirm is the guard the sponsor asked for: lastcall cannot tell who wrote the bytes, but the user knows whether they saved, so a prompt after a session with no save names an agent's write. **The blessing is a deliberate exception to invariant 3** ("never a fresh read"), made explicit by the confirmation: the editor session *is* the review, and the frozen §6.3 row is amended to say so (F3; Amendment v1.8, text in P1). The editor's own changed-on-disk warning (vim `W12`, VS Code, Emacs, Helix) is the guard *during* the session; lastcall documents that it relies on it. `Absent` (the editor deleted the file) or a symlink on return → nothing is written, status `<path>: <deleted|not a regular file> on return; left pending`.
