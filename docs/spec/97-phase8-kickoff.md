8. **The inline editor (TUI; gate item 1 through the UI; rulings P3, P5).** New keymap action `edit` (default `i`, `edit the file in place at the hunk under the cursor`). Opens on the same rows `edit_external` does **and only when the live bytes are valid UTF-8 and at most `collapse_size_bytes`** (else status `use shift-i: <why>`); the loop reads the file under the CAS (`Engine::read_rendered(root, rendered) -> Result<Vec<u8>, Refused>`: `cas_live` then `fs::read`) and the reducer opens `App.editor: Some(Editor { root, rendered, buf: TextBuf, marks: Vec<usize> (line numbers inside pending hunks at open, kept in step with insertions/deletions above them), line_at_open })`. *Layout:* the editor **replaces the diff pane** (the nav stays, dimmed; the header row shows `editing <path> · line <n>/<total> · ^S save   Esc close`), a 5-column line-number gutter with `▎` on marked lines, the cursor line highlighted, no soft wrap. *Keys:* every deliverable-4 key; `Ctrl-S` → `Effect::Save { root, rendered, bytes: buf.text() }`; `Esc` with a clean buffer closes, with a dirty buffer opens the confirm `Discard changes to <path>?` (`y` closes, `n` stays); `ctrl-c` quits as everywhere (a dirty buffer is lost — the confirm is not owed on quit, same as the note modal); mouse clicks inside the editor move the cursor, the wheel scrolls; keymap letters are text. *Save answers:* `Local::Saved` → close the editor, select the same row (or the next one if the row vanished), status `saved <path>`; `Refused::Moved` → the editor **stays open with its buffer**, status `<path>: changed since you opened it; not saved — Esc, then i to reload`, and the header turns red until a key is pressed; any other refusal closes nothing and names itself. *Tests:* reducer `app_edit_opens_at_the_hunk_line_and_marks_its_lines`, `app_edit_dirty_esc_asks_and_clean_esc_closes`, `app_edit_save_refused_keeps_the_buffer`, `app_edit_marks_follow_insertions_above_them`, `app_edit_refuses_binary_and_oversize_rows`; PTY `pty_edit_inline_save_pends_nothing` (`i` on `f1` hunk 2, type a line, `Ctrl-S`; the file on disk has it, the row's pending is the rest of the delta, zero for the saved content — gate item 1 through the UI) and `pty_edit_inline_save_refused_when_the_file_moved` (a second-shell write between `i` and `Ctrl-S` → the refusal line, the buffer still on screen, the file holds the second shell's bytes). *Snapshots:* `tui_editor_open` (100×30, the gutter marks visible), `tui_editor_dirty_confirm`, `tui_editor_save_refused`, `tui_editor_narrow_60x20`.
9. **Select-to-copy (TUI; gate item 3; ruling P6 for the payload).** New keymap actions `select` (default `v`, `start / extend a selection in the diff`) and `copy` (default `y`, `copy the selection (or the hunk under the cursor) to the clipboard`). *Keyboard:* `v` in the diff anchors a selection at the cursor line; `nav_up`/`nav_down`/`page` extend it (the diff cursor moves as usual, the selection is `anchor..=cursor`); `y` copies and clears; `Esc` clears without copying; `y` with no selection copies the hunk under the cursor whole. *Mouse:* press in the diff body anchors, drag extends, release copies (a press-and-release on one line is a click as today, not a copy); the row range is what is selected — never partial lines. *Rendering:* selected lines in reverse video (`inverse_at` proves it); the hint line shows `v select   y copy` while the diff has focus and the width allows. *Payload:* the selected diff lines **as shown**, prefix markers included (` `, `+`, `-`), hunk headers included when the range covers them, `\n`-joined with a trailing newline; a `y` on a hunk copies the hunk header and its lines. *The write:* `Effect::Copy(bytes)` → `run.rs` writes `ESC ] 52 ; c ; <base64> BEL` to stdout through crossterm's `execute!` (a `Command` impl in `tui/clipboard.rs`, base64 hand-rolled and unit-tested against RFC 4648 vectors) — **payload cap 64 KiB raw**; over the cap nothing is written and the status says `selection too large to copy (<n> KiB; the terminal would drop it)`. *The cue:* `App.cue: Option<Cue { text: "copied to clipboard", until: Instant }>` set on a successful write, rendered as a centred, `Clear`-backed one-line box over the diff pane, cleared by the tick when `now >= until` (**2 s**), independent of the status line (which is untouched by a copy); `Effect::Toast` (herdr) is not reused. *Tests:* reducer `app_select_extends_with_the_cursor_and_y_copies_the_range`, `app_y_without_a_selection_copies_the_hunk`, `app_copy_cue_lasts_two_seconds_and_leaves_the_status_alone`, `app_mouse_drag_selects_rows_and_release_copies`, `app_copy_over_the_cap_writes_nothing`; snapshots `tui_diff_selection`, `tui_copy_cue`, `tui_hint_diff_focus`. `SELECT_NOTE` stays (shift+drag is still the terminal-native path) and gains `, v/y copies via OSC 52`.

## Rulings

**Surfaced by this draft — presented to the sponsor after the design review; every Rec below is the build as drafted, every Alt stays on record:**

- **P1 What `$EDITOR` does to the baseline.** Rec: on return, if the file's hash changed, the override becomes whatever is on disk (invariant 8 for an external editor: the user's save is never pending); the residual — an agent that wrote the same file while the editor was open is blessed with it — goes on §11 with the trigger "an agent and the human editing one file concurrently becomes a workflow" and the mitigation that the diff pane showed the row's pre-edit delta a moment earlier. Alt: never bless an external editor's session — the user's edit shows as pending and one `a` clears it; right if the sponsor's agents write into files the human is editing, or if invariant 8 is read as "the tool's *own* editor" only (then the inline editor alone advances the baseline and gate item 1 is proven through it). Two-way door (a reducer branch).
- **P2 No `editor` config key.** Rec: `$VISUAL` → `$EDITOR` → `vi`, whitespace-split, no shell, a basename table for the line flag; an unknown editor opens without a line; §6.1 stays frozen and §11 records "unknown editors get no line flag; the table grows on request". Alt: an optional `editor = "code --goto {file}:{line} --wait"` template key (Amendment v1.8, sponsor-ratified) — right if the sponsor's editor is not in the table or takes a wrapper script; the resolution code is the same, only the source of the template differs. Two-way door, but a frozen-contract change.
- **P3 The inline editor edits the whole file, in the diff pane.** Rec: the whole file at the hunk's line, replacing the diff pane (context, the other hunks marked in the gutter, one mental model with `$EDITOR`); the save is one CAS'd write of the buffer. Alt: a hunk-scoped text box (only the hunk's new-side lines, spliced back with `apply_hunks` on save) — smaller widget, no horizontal scroll, right if the sponsor edits only inside agent hunks and never around them; the engine save would then need the hunk's range, not just bytes. Two-way door.
- **P4 What a whole-file flag exports.** Rec: the `whole file` header segment and a one-line summary (`<n> hunks · +<a> −<d>`), no diff: the agent knows the file and the human's note is the point; the summary tells it the scale. Alt: the file's full diff under a cap (say 200 lines, then `… <k> more lines`) — right if the sponsor's agents lose the file's context between the edit and the flag (a fresh session reading the export cold); costs a larger export and a second golden. Two-way door (the export shape is golden-pinned either way).
- **P5 Keys.** Rec: `i` inline edit, `shift-i` `$EDITOR`, `v` select, `y` copy, `Ctrl-S` save inside the editor, `Esc` close — the vi vocabulary the rest of the keymap already speaks (`j`/`k`, `n`/`p`, `u`), all `[keys]`-rebindable. Alt: `e`-family keys (`shift-e` for the editor, freeing `i`) and `c` for copy — right if the sponsor reads `i` as "info". Two-way door (defaults in a table).
- **P6 The copy payload is the diff as shown.** Rec: prefix markers and hunk headers included, because what the user selected *is* a diff and an agent reading a paste needs the `+`/`-`. Alt: the new-side text only, markers stripped (a paste that compiles) — right if the sponsor copies mostly to drop code into another file; could later be a second key. Two-way door.
- **P7 Richer fixture text = one new file in `alpha`.** Rec: `alpha/src/parse.rs` with three separated agent hunks; nothing existing changes, the golden and the nav snapshots regenerate once. Alt: a fourth root with the rich files — right if alpha's row count is load-bearing in more assertions than a grep shows; costs a root row in every nav frame instead. Two-way door.
- **P8 Worker split.** Rec: one Opus 5 worker with the checkpoint after deliverable 5 (the engine save, the editor command, and the text buffer are self-contained and the TUI half depends on all three). Alt: two workers on one branch (8a engine+buffer, 8b TUI against a stubbed `Engine::save`) — right if wall-clock matters more than the merge cost.
- **P9 The keyboard-enhancement probe is gated by an environment switch.** Rec: `LASTCALL_KEYBOARD=plain` skips `supports_keyboard_enhancement()` (the PTY harness sets it; no scene pays 2 s); default is to probe once at `enter()` and after every `$EDITOR` resume. Alt: never probe, push the flags only when `TERM` names a kitty-protocol terminal (`xterm-kitty`, `wezterm`, `foot`, `xterm-ghostty`) — no query round trip at all, right if the 2 s worst case on a silent terminal is unacceptable; misses iTerm2 and tmux `extended-keys`. Two-way door.
